## Z1. 보안 점검 (온라인 서버 · 클라이언트 · 저장)
조사에서 찾은 것과 고칠 것:
| # | 문제 | 위험 | 고침 |
|---|---|---|---|
| 1 | 다시 붙기 토큰을 `RandomNumberGenerator`(암호용 아님) 64비트로 만들고, **클라이언트가 보낸 토큰을 그대로 자리에 씀** | 남의 토큰을 추측하거나 지어내 끊긴 자리를 가로챔 | 토큰은 서버만 `Crypto.generate_random_bytes(16)`으로 만든다. 클라이언트 토큰은 끊긴 자리와 맞을 때만 「돌아오기」에 쓴다 |
| 2 | `hello` 없이 `create`·`join`·`act`가 됨 | 이름 · 토큰 없는 유령 자리 | `hello`를 마친 연결만 받는다 |
| 3 | 접속 수 · 방 수 · 메시지 빈도 제한 없음, 받는 버퍼 1MB | 메시지 폭탄 · 방 만들기 폭탄으로 서버 멈춤 | 전체 접속 · 방 상한, 연결당 초당 메시지 상한(넘으면 끊음), 받는 버퍼 64KB, `hello` 없이 10초면 끊음 |
| 4 | 방 코드 맞히기에 횟수 제한 없음 (32⁵) | 남의 방 찾아 들어가기 | 연결당 틀린 코드 10번이면 끊음 |
| 5 | 이름에 `[` `]`(BBCode) · 제어 문자 | 작전 기록(RichTextLabel)에 서식 · 링크 주입 | 서버에서 거르고, 클라이언트 기록 띠에서도 글을 이스케이프 |
| 6 | 서버가 판마다 데이터를 다시 읽음 | 부하 | 한 번만 읽어 둔다 |
- 확인만 한 것: `bytes_to_var`와 저장의 `get_var`는 객체를 풀지 않는다(기본값). 엔진 `apply()`는 합법 액션 목록과 견주므로 지어낸 액션이 통하지 않는다.
- 시험(`v2_net_test`)에 더할 것: 지어낸 토큰으로 자리 가로채기 실패, `hello` 없이 방 만들기 실패, 메시지 폭탄을 보내면 끊김, 이름의 BBCode가 걸러짐.

## Z2. 웹 멀티플레이
- 서버 주소 · 시간 값은 데이터(`data/v2/online.json`)로 뺀다. 웹판은 `wss://` 주소가 있을 때만 「온라인」을 보인다.
- 서버 배포: Render 무료 웹 서비스(`render.yaml` · `deploy/render/Dockerfile`, 소스를 Godot 헤드리스로 바로 돌림, Render가 TLS를 맡아 `wss://`). 서버는 `PORT` 환경 변수를 따른다. 잠든 서버를 깨우는 동안 클라이언트는 「깨우는 중」을 보이며 다시 붙는다. 배포 순서 문서.
- 계정 · 결제 · 실제 배포는 사용자가 한다.

## Z3. 데이터 구조 (포트폴리오용)

## Z5. 성능
- 측정: 화면이 한 프레임에 쓰는 시간(보드 그리기 · 기운 보드 · 갱신), 엔진 `legal_actions` · AI `decide` 시간, 서버 `view_for`.
- 고칠 후보: 매 프레임 다시 그리기, 기운 보드 SubViewport를 늘 갱신, 같은 계산 반복(`legal_actions`를 프레임마다 여러 번).
- 전후 수치를 적는다.

## Z1 결과 (2026-10-08)
- 고친 것(위 표 1~6 모두)
  - 토큰: 서버가 `Crypto` 128비트로만 만든다. 클라이언트 토큰은 끊긴 자리와 맞을 때만 받는다. 인사는 한 연결에 한 번이다.
  - 인사(hello) 전에는 다른 요청을 받지 않는다. 인사 없이 10초가 지나면 끊는다.
  - 상한: 동시 접속 256, 방 128, 연결당 초당 메시지 30(넘으면 끊음), 받는 버퍼 64KB.
  - 없는 방 코드를 10번 틀리면 끊는다. 오류 글에 코드를 되돌려 주지 않는다.
  - 이름에서 제어 문자와 `[ ] { } < > \`를 빼고 12자까지로 자른다(`NetServerV2.clean_name`). 클라이언트 작전 기록 띠는 `[`를 `[lb]`로 바꿔 BBCode로 읽지 않는다.
  - 서버는 데이터를 한 번만 읽는다.
- 시험(`v2_net_test`)에 5개를 더했다: 지어낸 토큰 거절과 자리 못 얻음, 인사 없는 방 만들기 실패, 메시지 폭탄은 끊김, 방 코드 10번 틀리면 끊김, 이름 서식 걸러짐. 결과는 12/12(사람 2명), 11/11(사람 1명).
- 확인만 한 것(문제없음)
  - `bytes_to_var`와 `FileAccess.get_var`는 객체를 풀지 않는다.
  - `apply()`는 합법 액션과 견주므로 지어낸 액션이 통하지 않는다. 남의 자리 행동도 거절한다.
  - 저장 파일이 깨졌으면 지운다.
  - `OS.shell_open`은 플레이테스트 폴더만 연다.
- 남은 위험: 서버는 `ws://`로만 말하고 TLS는 앞단(Render 프록시)이 맡는다(Z2). 연결이 끊긴 뒤 다시 붙을 수 있는 토큰은 판이 끝날 때까지 유효하다.

## Z4 결과 (2026-10-08)
- `game_screen_v2.gd` 2,875줄 → 1,350줄. 화면에는 상태 · 화면 짜기 · 흐름(입력 → 행동 → 연출 큐 → AI 차례)만 남겼다. 나머지는 역할별 모듈로 옮겼다.
  | 파일 | 맡는 일 |
  |---|---|
  | `screen_actions_v2.gd` | 행동 단추판 · 주사위 · 보조 단추 · 주사위 메뉴 · 못 하는 이유 · 상태 줄 |
  | `screen_playback_v2.gd` | 이벤트 연출 재생 · 빠르기 · 연출 설정 · 기다림 측정 |
  | `screen_text_v2.gd` | 행동 이름 · 조건 문장 · 큰 카드 설명 사전 |
  | `screen_coach_v2.gd` | 훈련 할 일 · 단계별 안내 · 첫 판 도움말 |
  | `screen_preview_v2.gd` | 선택 미리보기 띠 (갈 곳 · 얻는 것 · 위험) |
- 모듈은 화면(`scr`)을 받아 그 일만 하고, 판 상태는 화면 한곳에 둔다. 한 모듈만 쓰는 변수(컷신 본 횟수, 주사위 메뉴, 훈련 할 일 등)는 그 모듈로 옮겼다. 다른 곳에서 부르는 함수는 앞 밑줄을 뗐다.
- 옮기기는 변환 도구로 기계적으로 했다. 함수를 통째로 옮기고 화면 멤버 참조에 `scr.`를 붙였다. 그다음 Godot 파서와 시험으로 확인했다.
- 같은 일을 하던 코드 모음: 요원 이름 만들기가 다섯 곳(보드 이름표 · 기운 보드 · 위 띠 · 판 화면 · 엔딩)에 흩어져 있던 것을 `text_v2.gd`(`TextV2`)로 모았다. 마커 역할 이름은 `ui.json`의 `marker_names`로 옮겼다.
  - 고친 버그: 위 띠가 「나」를 `pid == 0`으로 정해서, 온라인에서 내 자리가 0번이 아니면 리더 이름이 틀렸다. 이제 판의 사람 자리(`RulesV2.human`)로 정한다.
- 확인
  - 화면 시험 2판 · 그림 없음 + 평면 보드 1판 · 투어(q · v2 · v2f · endings · online) · 규칙 · 데이터 · 온라인 시험 모두 통과
  - 안내 말풍선 캡처가 나누기 전과 픽셀 단위로 같다
  - 종료 때 누수 경고 수(10 · 20)도 나누기 전과 같다(원래 있던 것)

## Z5 결과 (2026-10-08)

- 한 판(사람 4명, 약 300수) 동안 서버가 내보내는 양: 약 30MB → 약 3.3MB. Render 무료 대역폭을 덜 쓴다.
- 고치지 않은 것(재 보니 작음): 엔진 `legal_actions` 0.05~0.19ms, `apply` 0.08~0.26ms, AI 한 수 0.5~1.5ms. 화면 갱신마다 `legal_actions`를 몇 번 부르지만 갱신은 행동할 때만이라 프레임에 영향이 없다. 기운 보드 SubViewport는 매 프레임 그리지만 GPU 일이고 위 프레임 시간에 이미 들어 있다.
- 시험: 온라인 시험에 2개 더함(새 줄만 받아 이어 붙인 기록이 서버 기록과 같음, 큰 메시지는 압축되고 풀림). 처음 한 번은 마지막 보기가 오기 전에 비교해서 틀려, 마지막 보기를 기다리게 고쳤다. 그 직후 두 번은 클라이언트 기록이 중간에서 멈춘 채로 틀렸는데 원인을 찾지 못했다(진단 출력을 더한 뒤 연속 15번 통과, 다시 나오지 않음). 클라이언트는 풀지 못한 패킷이 오면 「못 푼 패킷」을 찍는다.
- 프로토콜 버전 1 → 2. 예전 웹판은 새 서버에 붙지 못하므로(「게임 버전이 서버와 다릅니다」) 웹판과 서버를 같이 올린다.
