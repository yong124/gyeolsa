# 조사: 튜토리얼은 어떻게 가르쳐야 하나 (2026-10-12)

> 계기: T2 튜토리얼을 직접 해 본 사용자가 「덮인 타일을 뒤집으며 이동한다 같은 **기초 설명이 아예 없다**」고 지적했다. T2는 정보 과다를 덜어 내는 데 집중하다가, 게임의 바탕이 되는 개념까지 같이 덜어 냈다. 그래서 튜토리얼 설계 원칙을 다시 조사했다.

## 1. 조사한 것과 핵심

| 출처 | 핵심 | 결사에 주는 뜻 |
|---|---|---|
| 보드게임 가르치는 법 (Asmodee, Bumbling Through Dungeons 등) | **주제 한두 문장 → 목표(어떻게 이기나) → 판의 흐름을 간단히 → 평범한 한 차례를 실제로 해 보기 → 세부는 필요할 때.** 처음부터 예외나 카드 글귀를 말하면 「왜 중요한지 모르는 정보」가 된다. 첫 차례는 가르치는 사람이 **시범**을 보이며 왜 그렇게 하는지 말한다 | T2는 「흐름 스케치」와 「판의 기초(덮인 지도, 출발점·거점)」를 통째로 뺐다. **큰 그림은 짧게라도 먼저** 줘야 한다. 동료가 먼저 시범을 보이게 할 수 있다 |
| Super Mario Bros. 1-1 (미야모토 인터뷰, 분석) | 설명서 없이 기본 동작을 익히게 하는 것이 목표였다. **판의 배치가 가르친다**: 빈 오른쪽이 「오른쪽으로 가라」를 알려 주고, 첫 굼바가 점프를 하게 만든다 | 말보다 **판을 짜서** 하게 만든다. 예: 마커까지 가는 길을 덮어 두면, 걷기만 해도 「덮인 칸이 뒤집힌다」를 겪는다 |
| 기승전결 레벨 설계 (마리오 3D 월드, Game Maker's Toolkit) | 한 메커니즘을 **소개(안전하게) → 발전 → 비틀기 → 마무리** 순서로 몇 분 안에 가르친다 | 훈련 하나에 개념 하나를 기승전결로 짠다. 예: 판정(쉬운 선택) → 결과 → 대가(경찰) → 해결(숨기) |
| Gloomhaven: Jaws of the Lion | 처음 다섯 시나리오가 튜토리얼이다. 시나리오마다 규칙을 조금씩 더한다. **첫 판에는 아주 쉬운 카드만** 주고, 가르치는 글을 강조해 둔다 | 훈련마다 **쓸 수 있는 행동과 보이는 정보를 줄인다**(단계적 공개). 훈련 1에는 이동과 바치기만 보인다 |
| Into the Breach | 처음 몇 턴은 이동과 공격만, 위험 요소와 적은 하나씩 더한다. 규칙을 다 말하지 않고 **통제된 노출로 익히게** 한다. 전략은 실패로 배운다 | 튜토리얼은 **메커니즘**을 가르치고, 전략은 실전에 맡긴다 |
| Andersen 외, CHI 2012 (4만 5천 명 실험) | 튜토리얼의 효과는 **게임 복잡도에 달렸다.** 가장 복잡한 게임에서만 플레이 시간이 최대 29% 늘었고, 단순한 게임에서는 효과가 없었다 | 결사는 복잡한 쪽이다. 튜토리얼에 투자할 가치가 있다. 다만 **실험해서 알 수 있는 것은 굳이 가르치지 않는다** |
| GameDev.net 「7 UX Lessons」, Roblox 온보딩 문서, 인디 개발자 경험담 | **사람은 글 덩어리를 읽지 않는다.** 한 번에 보여 준 설명은 실패했고, 단계별로 그 자리에서 보여 주는 안내로 바꾸니 통했다. 글 팝업은 놓치기 쉽다. **할 때가 되었을 때(just-in-time)** 짧게 알려 준다 | T2의 「60자, 개념 하나」는 맞다. 다만 **줄이는 것과 빼먹는 것은 다르다.** 기초는 짧게라도 꼭 넣는다 |
| Celia Hodent, 「The Gamer's Brain」(GDC 2016 온보딩 강연) | 인지과학으로 본 온보딩: 사람의 주의와 기억은 좁다. 해 보며 배우고(learning by doing), 그 맥락에서 배우고, 바로 피드백을 받고, **되풀이해야** 기억에 남는다 | 한 번 해 본 개념은 **다음 훈련에서 또 쓰게** 한다(되풀이). 이동은 모든 훈련에서 다시 한다 |
| 디지털 보드게임(Spirit Island · Pandemic 앱) | 앱의 장점은 **장부 정리를 대신 해 주는 것**이다. Spirit Island 앱의 자세한 튜토리얼은 종이 설명서보다 낫다는 평을 받는다 | 계산·처리는 게임이 하고, 사람에게는 **결정**만 가르친다 |

## 2. 결사 튜토리얼에 적용할 원칙 10개
1. **큰 그림부터, 짧게.** 시작할 때 「작전 브리핑」 카드 한 장으로 목표, 두 막, 하루의 흐름을 그림과 세 줄로 보여 준다. 말풍선으로 길게 쓰지 않는다.
2. **판의 기초는 겪게 한다.** 덮인 지도, 출발점과 거점, 상하좌우 이동, 타일 효과, 같은 칸에 서기를 말로 늘어놓지 않는다. 판을 그렇게 짜 두고 **해 본 직후 한 줄로** 짚는다.
3. **시범 → 따라 하기.** 새 행동은 동료(AI)가 먼저 해 보이고, 그다음 내가 한다. 보드게임에서 가르치는 사람이 첫 차례를 시범 보이는 것과 같다.
4. **훈련 하나 = 개념 하나를 기승전결로.** 소개 → 해 보기 → 대가나 변화 → 해결 → 정리(배운 것 3줄).
5. **단계적 공개.** 훈련마다 행동 단추와 위쪽 정보를 필요한 것만 보이게 한다(1: 이동·바치기 → 2: +작전 판정·숨기 → 3: +건네기 → 4: 전부).
6. **되풀이.** 앞에서 배운 것을 다음 훈련 첫머리에서 다시 쓰게 한다(이동은 매번, 판정은 2·3·4에서).
7. **선택은 의미 있게, 실패는 안전하게.** 「5와 2 중 무엇을 낼까」처럼 이 게임의 핵심 고민을 직접 고르게 한다. 잘못 고르면 이유를 말해 주고 다시 고르게 한다.
8. **바로 피드백.** 행동마다 화면 반응(뒤집힘, 도장, 게이지 오름)이 먼저 나오고, 그다음 한 줄 설명을 붙인다.
9. **글은 짧게, 말투는 「~다」체.** 말풍선은 60자 안에 개념 하나만 담고, 목록은 넣지 않는다. 사용자 결정(2026-10-12)에 따라 해요체 대신 「~다」로 맺는다(예: 「덮인 칸에 들어가면 타일이 뒤집힌다.」).
10. **전략은 실전에, 참고는 도움말에.** 튜토리얼은 「어떻게 하나」만 가르친다. 「언제 결행할까」 같은 전략은 실전과 실패로 배운다. 목록은 「?」 도움말과 처음 나올 때 뜨는 쪽지가 맡는다.

## 3. T2와 비교
| 원칙 | T2 | 바꿀 것 (T3) |
|---|---|---|
| 큰 그림부터 | 첫 말풍선 하나(목표)만 있음 | 작전 브리핑 카드(목표 · 두 막 · 하루) |
| 판의 기초를 겪게 | 길을 미리 깔아 **타일이 안 뒤집힘** | 길을 덮어 두고, 뒤집힌 뒤에 짚음 |
| 시범 → 따라 하기 | 없음 | 훈련 1에서 동료가 먼저 걸어 타일을 뒤집음 |
| 단계적 공개 | 처음부터 행동 8개와 위쪽 정보 전부 | 훈련마다 보이는 행동 · 정보를 줄임 |
| 되풀이 | 이동은 훈련 1 · 2에서만 | 훈련 3에서도 이동으로 동료에게 다가감 |
| 노출 · 첩보 · 하루 흐름 | 없음 | 해 본 직후 한 줄 |
| 말투 | 해요체 | 「~다」체 (쪽지 · 도움말 포함) |
