# v2 구현 2단계: 엔진 1막

v2 규칙의 1막(정찰)을 돌리는 규칙 엔진을 만든다. 근거 문서: `결사_기획서.md` 19장(특히 19.3 하루 흐름, 19.4 팀 주사위, 19.11 공개 미션, 19.13 흉내 판에서 정한 것, 19.14 캐릭터, 19.15 실행 순서), `카드_목록_v2.md`, 1단계 결과 `game/data/v2/*.json`과 `game/scripts/core/v2/game_data_v2.gd`(GameDataV2), 어휘는 `v2_구현/1단계_데이터.md` 3절.

2단계는 둘로 나눈다. **2a**(뼈대)를 먼저 만들고 합친 뒤 **2b**(카드 효과)를 만든다.

## 0. 원칙

- **v1 코드는 고치지 않는다.** `scripts/core/rules.gd`, `ai.gd`, `game_data.gd`와 기존 테스트는 그대로 둔다. v1의 지도·경찰·판정 로직은 **읽고 옮겨 온다**(상속이나 호출 대신 복사·정리). v2 엔진은 v1 클래스에 의존하지 않는다 (보드 정보는 GameDataV2가 이미 v1 GameData에서 읽어 둠).
- 새 파일: `game/scripts/core/v2/rules_v2.gd` (class_name `RulesV2`), 테스트 `game/tests/v2_engine_test.gd`, `game/tests/v2_mechanics_test.gd`.
- v1과 같은 설계 원칙을 지킨다.
  - **모든 조작은 `apply(action) -> bool` 하나로.** 받아들인 액션은 `actions` 목록에 쌓인다.
  - **결정적:** 난수는 전부 `rng`(시드 고정) 하나로. 같은 시드 + 같은 액션 목록 = 같은 판.
  - **UI 알림은 `events` 큐로** (`_push`, v1처럼 그 순간의 요원·경찰 위치 스냅숏을 함께 담음).
  - `save_state()/load_state()`, `log_lines`, `history`(연표).
- **v2의 모든 액션은 `"player"` 키를 가진다.** 아침 계획 때는 여러 사람이 아무 순서로 액션을 보내고, 낮에는 차례인 사람만 보낸다. 엔진은 누가 보냈는지로 검증한다.
- **`legal_actions() -> Array`**: 지금 받아들일 수 있는 액션을 모두 돌려준다 (AI와 테스트가 쓴다). `apply`가 `true`를 돌려주는 액션과 정확히 같아야 한다.
- 문장(로그, 배너)은 한국어. v1 rules.gd의 말투를 따른다.
- 이번 단계에서 다루지 않는 것: 개인 사연, 심문 카드와 설득, 변절(3단계), 2막 장면 덱과 엔딩(4단계), AI(5단계), 화면(6단계). 해당 자리는 **빈 훅 함수**로 남긴다 (아래 표시 `훅`).

## 2. 요원

```
{"id", "name", "character": 캐릭터 id, "pos": Vector2i, "jailed": bool, "jail_count": int,
 "items": [], "bombs": int, "move_mod_next": int, "skip_dice_tomorrow": bool,
 "die": int (오늘 이동 주사위 값, 없으면 -1), "die_raw": int, "done_today": bool, "turns": int,
 "ability_day": int (능력을 쓴 날), "item_uses": int, "grants": [] (한 번 쓰는 권리, 19.7 보상),
 "flags": {}, "stats": {"missions", "rescues", "escapes", "jailed", "checkpoints", ...}}
```
- `stat(p, name)`: 캐릭터 특성 `mods` + 지속 아이템 `mods`를 합산 (v1 `stat()`과 같은 방식, 1단계 3-5절 stat 이름).
- 시작: 모두 출발점(가운데)에 섭니다. v1의 "started" 개념은 없습니다.

## 3. 하루 흐름

### 3-1. 아침 (phase "morning", 엔진이 자동으로 진행하다 선택이 필요하면 "choice")
순서는 기획서 19.3을 따른다.
1. **리더 넘기기:** 첫날은 0번, 다음 날부터 옆 사람(id + 1).
2. **위협 카드:** 덱 맨 위를 뒤집어 `threat_today`로 두고 효과를 적용 (2b의 효과 해석기). 덱이 비면 버린 카드를 섞어 다시 씀.
3. **결행 투표 (1막):** `ready >= rules.launch_min`이면 요원마다 한 표 (pending choice를 0번부터 차례로). 과반 찬성이면 결행. **동수면 리더의 표를 따름.** 또 `rounds_left <= rules.forced_launch_days_left`면 투표 없이 결행. 결행은 6절.
4. **변절 확인** `훅 _morning_traitor_check()` (3단계)
5. **미션 줄 채우기:** 남은 타일로 이룰 수 없는 미션은 줄에서 빼고, 줄을 `rules.mission_row`장으로 채움.
6. **팀 주사위 굴리기:** `인원 + rules.team_dice_extra + dice_extra_tomorrow`개를 굴림. 그 뒤 phase "plan".
- 아침이 시작될 때 `today`를 비우고, 요원마다 `die = -1`, `done_today = false`, `item_uses = 0`.

### 3-2. 계획 (phase "plan")
여러 요원이 아무 순서로 보냄.
- `{"type": "take_die", "player", "die": 인덱스}`: 그 주사위를 내 오늘 이동 주사위로. 이미 가진 주사위가 있으면 내려놓고 바꿈. 다른 사람이 가진 주사위는 못 가짐.
- `{"type": "release_die", "player"}`: 가진 주사위를 내려놓음.
- 감옥에 있는 요원은 주사위를 갖지 않아도 됩니다 (아무도 안 가진 주사위는 모두 예비).
- `skip_dice_tomorrow`인 요원은 오늘 주사위를 가질 수 없음.
- 아침에 쓰는 능력·아이템(`when: "morning"`)도 이 단계에서 씀 (2b).
- `{"type": "start_day", "player"}`: **감옥 밖 요원이 모두 주사위를 가졌으면** 누구든 보낼 수 있음. 남은 주사위는 예비가 되고 phase "day".
- 이동 주사위 값: 굴린 값 `die_raw`를 저장하고, 실제 값 `die`는 특성(`move_min3`: 1·2는 3) 적용 뒤의 값.

### 3-3. 낮 (phase "day" ↔ "turn")
- **자유 순서:** phase "day"에서 `{"type": "begin_turn", "player"}`. 오늘 아직 안 한 요원이면 누구든. phase "turn", `current = player`.
- 변절자는 늘 마지막 `훅` (3단계에서 begin_turn 검증에 추가).
- 차례 시작 때
  - 감옥에 있으면: `escape`(탈옥 판정), 옥중에서 쓸 수 있는 아이템(옷핀), `end_turn`(포기) 중 하나. 탈옥에 성공하면 경찰이 붙고 차례가 끝남 (v1과 같음). 실패해도 차례가 끝남.
  - 아니면: `steps_left = 이동값` (`die` + `move_mod_next` + `today.dice_mod`(최소 1) + `move_today` + 예비 주사위 더한 값). `move_mod_next`는 0으로 되돌림.
- 차례 중 액션: `step`(한 칸), `end_move`(남은 칸을 버리고 멈춤), `use_item`, `ability`, `give_item`, `decoy`, `use_spare`.
- **이동 끝:** 칸 효과(3-5) → 이 요원을 쫓는 경찰 이동(v1 `_police_act`) → `done_today = true`, phase "day", `current = -1`.
- 모두 `done_today`면 **밤:** `rounds_left -= 1`. 0이면 판 끝 (`ending.id = "time"`, 2단계에서는 1막 시간 종료가 거의 없음: 8/13 강제 결행이 먼저 옴). 아니면 다음 날 아침.

### 3-4. 예비 주사위
`{"type": "use_spare", "player", "die": 인덱스, "use": "move" | "reroll" | "escape"}`
- `move`: 지금 차례 이동에 그 눈을 더함 (차례 중, 이동 시작 전이나 중).
- `reroll`: 방금 실패한 판정을 다시 굴림 (판정 실패 직후 열리는 선택에서, 3-6).
- `escape`: 탈옥 판정에 그 눈을 더함 (탈옥 시도 전).
- 예비 주사위는 각각 하루 한 번. `persuade`(설득)는 3단계.

### 3-5. 지도와 칸 (v1에서 옮김)
- 타일 더미: `rules.tiles` 장수대로 만들어 섞음. 거점 4곳과 출발점은 처음부터 깔림. v2에는 전차 역이 없음.
- 빈칸으로 가면 더미 맨 위 타일을 깔고 들어감. 검문소가 새로 나오면 그 앞에서 멈춤. 이미 있는 검문소에 들어가려면 회피 판정 (실패: 노출 +1, 경찰, 이동 끝).
- **거점:** 들어가면 이동이 끝나고 경찰이 붙음. 예외: 지속 stat `base_no_police`, 이번 진입에 `entry_no_police` 권리. 그 거점 감옥에 갇힌 동료가 있으면 구출 (구출한 요원의 `rescued_move_bonus`를 구출된 동료의 `move_mod_next`에 더함).
- **멈춘 칸:** 이벤트 타일(처음 한 번) → 이벤트 카드, 아이템 타일(처음 한 번) → 아이템 카드, 보급 → 폭탄 (`bomb_slots`보다 적게 갖고 있고 `bomb_supply`가 남았을 때). 쓴 이벤트·아이템 타일은 일반 타일이 됨.
- **은신처** (`board[c].flags`에 "hideout"): 여기서 차례를 마치면 나를 쫓던 경찰이 사라짐.
- **이 차장 특성** `end_move_hop_to_ally`: 이동이 끝날 때 동료 옆의 **깔린 빈 칸**으로 한 칸 옮길지 선택 (2b).
- 같은 칸에 여러 요원이 설 수 있는지는 v1 `occupied_by_other`를 따름 (거점·출발점은 예외).
- `path_to(p, goal)`도 옮겨 온다 (화면의 경로 미리 보기용).

### 3-6. 판정
- 2d6 + 보정 ≥ 목표 (`rules.checks`). 회피 7, 암살 9, 탈옥 9, 방해 7.
- 보정: stat (`evade_bonus`, `assassin_bonus`, `escape_bonus`, `sabotage_bonus`), 오늘 효과(`escape_mod_today`), 한 번 쓰는 권리(`grants`의 `check_bonus`).
- 자동 성공: `evade_auto`(윤 소위), 권리 `evade_auto`, 아이템 연막탄(회피할 때 쓸지 묻는 선택).
- **실패 직후 다시 굴리기 선택:** 실패했고 다시 굴릴 수단(예비 주사위, `reroll` 권리, `assassin_rerolls` 특성 — 특성은 자동으로 한 번)이 있으면 pending choice로 묻는다. 고르지 않으면 실패로 처리.
- 판정 결과는 `{"kind": "dice", "what", "dice", "bonus", "target", "player"}`로 알림 (v1과 같음).

### 3-7. 경찰과 감옥 (v1에서 옮김)
- 요원마다 경찰 하나가 따로 붙음, 판 전체 `rules.police.pieces`개까지. 붙은 다음 차례부터 움직임 (`summon_turn`).
- 그 요원의 차례 끝에 그 요원을 향해 `speed`칸 이동. `speed = speed_by_alert[경계-1] + today.police_speed`(최소 1). 따라잡으면 체포 → 투옥.
- 경찰과 거리가 `escape_distance`를 넘으면 따돌림 (경찰 제거).
- **투옥:** 가장 가까운 거점의 감옥. `jail_count += 1`, 노출 +1, 경찰 제거. 훅 `_on_jailed(p)` (3단계: 심문 카드).
- **서 마담 특성** `block_police_with_evade`: 내게 경찰이 붙을 때 회피 판정, 성공하면 안 붙음 (2b).
- **경계:** 노출이 `exposure.thresholds`를 넘으면 경계 +1, 경계가 오를 때마다 무작위 거점에서 경찰 출동 (가장 가까운 요원을 쫓음).

### 3-8. 공개 미션 (19.11)
- 미션 덱(20장)을 섞어 두고, 아침마다 줄을 채움.
- **누구든** 조건을 채우면 이룸. 한 번의 행동으로 여러 장을 채우면 모두 이룸.
- 종류별 판정 (missions.json의 `types`):
  - 암살: 암살 타일에 **들어가는 순간** 판정 9. 성공: 결행 준비 +2, 노출 +1(시끄러움), 경찰이 붙음. 실패: 회피 판정, 실패하면 투옥 (v1과 같음).
  - 잠입: 카드의 `base`에 들어감.
  - 폭파: 폭탄을 가진 채 폭파 타일에 들어감 → 폭탄 1개 사용, 노출 +1.
  - 방해: 방해 타일에 들어가는 순간 회피 판정 7 (`sabotage_bonus`). 실패: 경찰.
  - 협동: 2b.
- 줄에 그 종류 미션이 없으면 그 타일에 들어가도 아무 일 없음. 같은 종류가 여러 장이면 한 번의 판정으로 모두 (판정은 한 번만).
- 이루면: `ready += 카드(또는 종류)의 ready`, `intel` 처리(카드의 `intel`: 거점 id / "nearest" / "entered"), `rewards` 효과 적용, 캐릭터 `mission_intel_bonus`(같은 종류면 첩보 +값). 카드는 줄에서 버림.

### 3-9. 협력 행동 (v1 유지)
- `give_item {player, index, to}`: 같은 칸이나 옆 칸 동료에게 아이템 1장. 아이템 사용 1회로 셈 (주모 막례 능력은 예외, 2b).
- `decoy {player, from}`: 3칸 안 동료를 쫓는 경찰을 나에게로 (차례당 1회).

## 4. 아이템과 손패 (뼈대는 2a, 카드별 효과는 2b)
- 손패 한도 `rules.hand_limit` + stat `hand_limit`. 넘으면 버릴 카드를 고르는 선택.
- 아이템 사용 `rules.item_uses_per_turn`(1)회/차례. 소모 카드는 쓰면 버림.
- `when`: "morning"(계획 단계), "turn"(내 차례), "react_evade"(회피 판정 직전에 묻기), "jailed"(갇혔을 때 내 차례), "any".
- 주모 막례 `item_draw_choice`: 아이템을 뽑을 때 2장 보고 1장 고름 (남은 1장은 버린 더미로).

## 5. 효과 해석기 (2b)
`_run_effects(p, effects: Array, ctx: Dictionary)` 하나로 위협·이벤트·아이템·능력·미션 보상의 효과를 모두 처리. 1단계 3-2절 op와 이번 합치기에서 더한 op(`if`, `interrogate_discard`, `threat_flip`, `check_or_jail`, `entry_no_police`)를 구현한다.
- 선택이 필요하면(`choice`, 대상 고르기, 동점 고르기) pending choice를 열고, 고른 뒤 남은 효과를 이어서 처리 (v1 `_ask` / `_resolve_choice` 방식처럼 "then" 이어가기).
- **동점은 그날의 리더가 고른다** (고립된 요원, 수배된 요원, 결행 목표 거점).
- 1막에서 쓸 일이 없는 op(`search`, `scene_check_mod_today`, `threat_flip`, `check_or_jail`, `refill_supply`)와 3단계 op(`interrogate`, `interrogate_discard`, `persuade`)는 **훅으로 남긴다**: 로그만 남기고 아무것도 안 함. `interrogate`는 1막 위협 「회유 공작」에서 실제로 나오므로, 훅 `_interrogate(p)`를 부른다.
- 캐릭터 능력: `ability {player, target?}`. 하루 1번 (`ability_day`). `when`이 "morning"이면 계획 단계에서만, "turn"이면 내 차례에만. `requires.near_tile`이면 그 타일 옆 칸에서만.
- 협동 미션 조건 (`cover_entry`, `same_day_assassin`, `people` + `where: adjacent` + `base`, `opposite_edges`)은 해당 순간(거점 진입 시, 차례 끝, 밤)에 확인.

## 6. 결행 선언 (2단계 임시)
- 결행하면 `launch_info = {"reason": "vote"|"forced", "day", "rounds_left", "ready", "exposure", "alert", "intel": 복사, "target": 거점 id}`. 목표는 첩보가 가장 많은 거점, 동점이면 리더가 고름.
- **2단계에서는 여기서 판을 끝낸다:** `act = 2`, `phase = "over"`, `ending = {"id": "launch_stub", "target": ...}`. 4단계에서 2막으로 이어 붙인다. 이 부분은 함수 하나(`_launch`)로 두고 `## 4단계에서 2막으로 이어짐` 주석을 단다.

## 7. 알림 (events)
v1과 같은 `{"kind": ...}` 모양. 최소한 다음을 쓴다: `morning`(day, leader), `threat`(id), `vote`(player, value), `launch`, `dice_rolled`(values), `die_taken`(player, die), `day_start`, `turn`(player), `move`, `reveal`, `dice`, `card`(deck: event/item/threat/mission), `mission_done`(id, player), `intel`, `ready`, `exposure`, `alert`, `police`, `catch`, `jail`, `rescue`, `banner`, `night`, `over`. 화면(6단계)이 이걸로 연출한다.

## 9. 테스트와 완료 기준

**`tests/v2_engine_test.gd` (2a에서 만들고 2b에서 늘림)**
- 4인, 시드 N개(기본 200). 캐릭터는 시드마다 무작위 4명.
- 각 판을 **`legal_actions()`에서 무작위로 고르는 봇**으로 끝까지 둔다 (`rng`와 다른 별도 난수로 고름).
- 확인:
  - `legal_actions()`의 모든 액션을 `apply`가 받아들임 (거부 0건). 반대로 무작위로 만든 잘못된 액션(남의 차례에 step 등)은 거부함.
  - 판이 끝남 (`launch_stub` 또는 `time`), 무한 반복 없음 (액션 수 상한).
  - 불변식: 하루에 요원마다 차례 한 번, 주사위는 한 사람에 하나, 경찰 ≤ 4, 미션 줄 ≤ 3, 손패 ≤ 한도, 칸이 보드 안.
  - **재생:** 같은 시드 + `actions`로 새 엔진을 돌리면 `save_state()`가 같음 (`log_lines`, `events`, `history` 제외).
  - **저장:** 중간에 `save_state()` → `load_state()` 한 엔진과 원래 엔진에 같은 액션을 주면 끝 상태가 같음.
  - 출력: 결행까지 걸린 날 평균, 강제 결행 비율, 미션 종류별 성공 수, 투옥 수.
