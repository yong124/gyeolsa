# 데이터 구조 — 결사 v2

> 규칙 수치 · 카드 · 문장 · 보드 · 화면 구성은 모두 `game/data/v2/*.json`에 있다. 코드는 **어휘(효과 · 조건의 종류)** 만 알고, 어떤 카드가 몇 장인지, 수치가 얼마인지는 모른다.
> 새 카드는 JSON만 고쳐서 더하고, 검증기가 오타 · 모르는 어휘 · 빠진 필드 · 장수 불일치를 잡는다.

## 1. 흐름

```
data/v2/*.json ──▶ GameDataV2 (읽기 · 색인 · validate) ──▶ RulesV2 (규칙 엔진, 판정)
                                                         ├─▶ GameAIV2 (AI 동료, 공개 정보 + 자기 사연만)
                                                         ├─▶ 화면 (GameScreenV2 · BoardViewV2 …, ui.json으로 구성)
                                                         └─▶ 온라인 서버 (NetServerV2, online.json으로 시간 · 상한)
```
- `GameDataV2.load_default()`는 한 번만 읽어 캐시한다. 시험 · 측정은 `load_dir(폴더)`로 사본 폴더를 읽을 수 있다.
- 엔진은 데이터에 적힌 효과(`{"op": ...}`)와 조건(`{"kind": ...}`)을 해석해 실행한다. 어휘 목록은 `game_data_v2.gd` 위쪽의 `KNOWN_*` 상수이고, 각 어휘의 뜻은 [1단계_데이터.md](1단계_데이터.md) 3절에 있다.

## 2. 파일별 내용

| 파일 | 담는 것 | 핵심 열쇠 |
|---|---|---|
| `board.json` | 보드 크기, 시작 칸, 결행 거점 4곳, 지도 그림 맞춤, 타일 그림 | `size` · `start` · `bases[{id, pos, name}]` · `map{image, px, origin, cell}` · `tile_art{종류: {texture, used_texture}}` |
| `rules.json` | 규칙 수치 전부 | 아래 3절 |
| `missions.json` | 미션 22장, 일제 작전 4장 | `missions[]` · `ops[]` · `types` |
| `threats.json` | 위협 카드 (1막 14장, 2막 8장) | `act1[]` · `act2[]` |
| `scenes.json` | 결행 거점 4곳의 장면, 경비 강화 4장 | `strikes{거점id: {entry, middle[], final}}` · `reinforce[]` |
| `characters.json` | 소속 4개, 요원 12명 | `factions` · `characters[]` |
| `sagas.json` | 개인 사연 20장, 결과별 후일담 | `piles` · `sagas[]` |
| `events.json` · `items.json` | 이벤트 10종, 아이템 10종 | `events[]` · `items[]` |
| `endings.json` | 엔딩 제목 · 문장 (거점별, 실패 갈래) | `victory` · `fail_final` · `operation` · `history` · `strikes{거점id}` |
| `ui.json` | 화면 구성 (규칙과 무관) | `verbs[]` · `mission_art` · `marker_glyph` · `weather` · `training_tasks[]` |
| `online.json` | 온라인 서버 주소 · 시간 · 보안 상한 | `server_url_web` · `wake_wait` · `human_idle` · `limits{}` |

`_comment`나 `_`로 시작하는 열쇠는 설명이고, 읽는 쪽이 건너뛴다.

### 카드 한 장의 모양 (공통)
```json
{"id": "train_ticket", "name": "승차권", "count": 2, "text": "오늘 내 이동 주사위 +3",
 "when": "turn", "effects": [{"op": "move_today", "who": "self", "value": 3}]}
```
- `id`: 영문 고유 열쇠. 저장 · 로그 · 온라인 메시지는 id만 주고받는다.
- `count`: 덱에 들어가는 장수. 검증기가 기준 장수와 견준다.
- `text`: 화면에 보이는 문장. **효과는 `effects`가 정하고 `text`는 사람용**이다. 둘이 어긋나지 않게 검수한다.
- `effects`: 순서대로 실행되는 효과 목록. `op`가 어휘이고 나머지는 인자다(`who` 대상, `value` 값, `base` 거점 …).

### 미션 (missions.json)
```json
{"id": "m_police_chief", "name": "순사 부장 암살", "type": "assassin",
 "condition": {"kind": "assassinate", "check": "assassin", "target": 9, "risky": true},
 "markers": [{"role": "target", "around": "police_hq", "min": 2, "max": 3, "move": 1}],
 "deadline": 4, "missed": [{"op": "exposure", "value": 1}],
 "ready": 2, "rewards": [{"op": "intel", "base": "police_hq", "value": 2}],
 "bonus": {"if": {"kind": "not_chased"}, "reward": [...], "text": "..."}}
```
- `condition.kind`: 미션 종류(암살 · 잠입 · 폭파 · 공작 · 연락 · 잠복 · 협동 …). `KNOWN_MISSION_KINDS`.
- `markers`: 보드에 놓는 마커. `role`(표적 · 정보원 · 공작 칸 …)과 `around`(어느 거점 둘레 몇 칸).
- `deadline` · `missed`: 며칠 안에 못 하면 생기는 벌칙. `ready` · `rewards`: 이루면 오르는 결행 준비와 보상.

### 요원 (characters.json)
```json
{"id": "yun", "name": "윤 소위", "faction": "kb", "persona": "bold",
 "trait": {"mods": [{"stat": "evade_auto", "value": 1}]}, "trait_text": "회피 판정 항상 성공",
 "ability": {"name": "무전 지원", "when": "morning", "target": "self",
             "effects": [{"op": "die_reroll", "count": 1, "scope": "any"}]}}
```
- `trait.mods`: 늘 붙는 능력치 보정(`KNOWN_STATS`). `ability`: 하루 한 번 쓰는 능력(효과 어휘는 카드와 같다).
- `persona`: AI가 이 요원을 둘 때의 성향. `rules.json`의 `ai.persona`에 있는 열쇠여야 한다.

### 사연 (sagas.json)
- `condition`: 이루는 조건(`KNOWN_SAGA_CONDITIONS`). `reward`: 이뤘을 때 효과.
- `epilogue`: 결과 네 갈래(`win_done` · `win_fail` · `lose_done` · `lose_fail`)의 후일담. 넷 다 있어야 한다.

## 3. rules.json 주요 묶음
| 묶음 | 뜻 |
|---|---|
| `rounds` · `personal_dice` · `die_sides` | 작전 일수, 아침 주사위 수, 주사위 면 |
| `launch_min` · `forced_launch_days_left` | 결행 투표에 필요한 준비, 강제 결행이 되는 남은 날 |
| `launch.vote` | 결행 투표 통과: `pass_ratio`(찬성 비율이 이것을 넘으면 통과), `tie`(딱 같을 때: `leader` 리더 찬성이면 통과 · `pass` · `fail`) |
| `launch.benefits` | 결행 혜택 후보 |
| `exposure` · `police` · `jail` | 노출 단계, 경찰 속도 · 출동 거리(`spawn_min_distance`), 투옥 |
| `tiles` · `tile_effects` | 타일 종류별 장수(합 100), 밟았을 때 효과 |
| `scenes` · `counter` · `ops` | 2막 장면 진행, 반격, 일제 작전 |
| `funds` · `market` · `checkpoint` | 군자금, 장터 값, 검문 |
| `ai` | AI 가중치: `act2_days_per_scene`, `saga_value`, `rescue{value, range}`, `persona{성향: {risk, vote}}`, `launch_target`, `mission`, `funds` |

## 4. 더하는 법

**새 미션**
1. `missions.json`의 `missions[]`에 카드를 더한다. 종류 · 마커 역할 · 보상 어휘는 이미 있는 것에서 고른다.
2. 장수 기준이 바뀌면 검증기의 기준 장수도 고친다(`_validate_missions`).
3. 그림이 없으면 `ui.json`의 `mission_art`에서 종류별 기본 그림이 쓰인다.
4. 검증 → 밸런스 측정(5절)으로 성공률과 승률 변화를 본다.

**새 요원**: `characters.json`에 더한다. 소속(`faction`)과 성향(`persona`)은 있는 열쇠로, 능력 효과는 카드 어휘로 쓴다. 초상은 `assets/art/char/<id>.webp`.

**새 위협 · 이벤트 · 아이템**: 해당 파일에 `count`와 `effects`로 더한다. 위협에 날씨 연출을 붙이려면 `ui.json`의 `weather`에 id를 넣는다.

**수치만 바꾸기**: `rules.json`을 고친다. 고치기 전에 `sweep=`으로 여러 값을 재 본다(5절).

**새 어휘(효과 · 조건 종류)**: 이때만 코드를 고친다. `RulesV2`에 실행을 더하고, `KNOWN_*` 목록과 [1단계_데이터.md](1단계_데이터.md)에 뜻을 적는다. 규칙 시험(`v2_mechanics_test`)에 사례를 더한다.

**거점**: 결행 장면 · 엔딩 · 미션이 거점 id로 이어져 있다. 이름과 칸은 `board.json`에서 바꿀 수 있지만, 거점 수는 4곳으로 고정이다(검증기가 확인).

## 5. 검증 · 측정 도구
```bash
# 데이터 검증: 오타 · 모르는 어휘 · 빠진 필드 · 장수 · 그림 경로
godot --headless --path game --script res://tests/v2_data_test.gd
# 검증기가 실제로 오류를 잡는지 (일부러 망가뜨린 예시)
godot --headless --path game --script res://tests/v2_validator_selftest.gd
# 밸런스: AI 4명 판 1,000판의 승률 · 엔딩 분포 · 사연 성공률
godot --headless --path game --script res://tools/v2_balance.gd -- games=1000
# 수치 실험: 값 하나를 바꿔 재기 / 여러 값을 나란히 재기 (파일은 바꾸지 않음)
godot --headless --path game --script res://tools/v2_balance.gd -- games=500 set=police.spawn_min_distance=4
godot --headless --path game --script res://tools/v2_balance.gd -- games=500 sweep=launch_min=2,3,4
```
- 게임이 시작될 때도 `validate()`가 돌아서, 오류가 있으면 콘솔에 「v2 데이터 오류」로 찍힌다.
- 규칙 시험은 고정 사본(`tests/fixtures/v2_base`)으로 돌아서, 밸런스 수치를 바꿔도 규칙 시험이 흔들리지 않는다.

## 6. 일부러 코드에 남긴 것
| 항목 | 이유 |
|---|---|
| 효과 · 조건 어휘의 실행 (`RulesV2`) | 어휘가 곧 규칙 엔진이다. 데이터는 어휘를 조합한다 |
| 화면 배치 크기 (`DOCK_H` · `LEFT_W` · 보조 단추 수 등) | 글자 잘림 · 겹침과 묶인 배치 값이라 화면 코드와 함께 바꾼다 |
| 행동 단추의 특수 안내 (2막 「작전 판정」 이유 등) | 규칙 상태를 읽어 문장을 만드는 화면 논리 |
| 저장 형식 (`SAVE_FIELDS`) | 판 상태의 구조이지 기획 값이 아니다 |
