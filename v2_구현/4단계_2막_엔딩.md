## 0. 원칙 (지난 단계와 같음)

- **데이터 주도.** 엔진에 장면, 카드, 사연, 캐릭터 id를 쓰지 않는다.
  - 장면은 `condition.kind`, `where`, `on_fail`의 op로만 움직인다.
  - 숫자는 `rules.json`에서 읽는다. 새 숫자는 키를 더하고 `_comment`를 단다.
  - 문장은 데이터 파일에 둔다.
  - 테스트는 상태를 꾸밀 때 id를 써도 된다.
- **결정성과 단일 진입점**
  - 모든 조작은 `apply(action)`로 한다.
  - 난수는 `rng` 하나만 쓴다.
  - 같은 시드와 같은 `actions`이면 같은 판이 나온다.
  - 새 상태는 모두 `SAVE_FIELDS`나 `players[i]`에 넣는다.
- `legal_actions()`는 `apply()`가 받아들이는 액션과 정확히 같아야 한다.
- **UI 알림은 `_push({"kind": ...})`로**, 연표는 `_record`, 배너는 `_banner`, 로그는 `_log`로 남긴다. 문장은 한국어로 쓰고 기존 말투를 따른다.
- **v1 코드는 고치지 않는다:** `scripts/core/rules.gd`, `ai.gd`, `game_data.gd`, v1 테스트.
- **이번 단계에서 하지 않는 것**
  - AI (5단계). 테스트는 무작위 봇으로 한다.
  - 화면 (6단계)
  - 2·3인 조정
  - 밸런스 수치 맞추기 (5단계)

## 1. 결행 순간에서 2막으로

지금의 `_launch_end()`가 판을 끝내는 자리다. 이를 `_begin_act2()`로 바꾼다. 결행 순간 처리 순서는 다음과 같다.

1. 결행 목표를 정한다.
2. 결행 순간에 세는 사연을 확인한다.
3. 사연 남기기를 한다.
4. 변절을 확인한다.

(1~4는 3단계에 이미 있다.) 그다음 아래를 한다.

1. `act = 2`. `launch_info.target`이 결행 거점 id다.
2. **위협 덱 교체:**
   - 1막 덱과 버린 카드를 치운다.
   - `data.threat_deck(2)`로 2막 덱을 만들어 섞는다.
   - `deck_place: "top_half"`인 카드는 섞은 뒤 덱 위쪽 절반 안의 무작위 자리로 옮긴다.
   - 덱은 배열 끝이 맨 위다 (`pop_back`).
3. **공개 미션 줄 정리:** 줄과 덱을 비우고, 2막에는 채우지 않는다. 결행 준비 수치(`ready`)는 더 쓰지 않는다.
4. **첩보 토큰:** `intel_tokens = intel[target]`. 첩보 토큰은 팀이 함께 쓴다.
5. **장면 덱 만들기** (`scenes.json`의 `strikes[target]`):
   - 진입 장면, 중간 장면 `rules.scenes.middle_draw`장, 마지막 장면을 놓는다. 중간 장면은 `middle` 중에서 무작위로 고른다.
   - 경계 단계 `alert_level()`에 맞춰 `rules.scenes.reinforce_by_alert[str(단계)]`장의 「경비 강화」 장면(`reinforce`, 무작위)을 더한다.
   - 「경비 강화」 장면은 진입과 마지막 **사이**의 무작위 자리에 넣는다.
   - 결과는 `scenes: Array[String]`(장면 id 순서), `scene_index := 0`이다.
   - 첫 장면을 공개한다: 알림 `{"kind": "scene", "index", "id"}`, 로그, 배너.
6. **결행 시작 효과:** `strikes[target].on_launch`를 실행한다 (예: `refill_supply`).
7. 판을 끝내지 않고 하루를 이어 간다.
   - 결행은 아침 투표나 강제 결행으로 일어난다. 이때 아침은 `morning_step`으로 진행 중이다.
   - 아침 남은 순서(변절 확인, 미션 줄, 팀 주사위)를 그대로 이어 간다. 변절 확인은 이미 했다. 미션 줄은 2막이라 건너뛴다.
   - 결행 순간의 선택(목표 고르기, `saga_keep`)이 끝난 뒤에도 아침이 이어지게 한다.
8. 알림 `{"kind": "launch", "reason", "target"}`, 배너 "결행!", 연표를 남긴다.

`launch_stub`과 관련된 임시 코드와 주석(`## 4단계에서 2막으로 이어짐`)은 지운다. `v2_engine_test`의 `launch_stub` 기대도 고친다.

## 2. 2막의 하루

1막과 같은 흐름이고, 다른 점만 적는다.

- **아침 순서:** 위협 → (투표 없음) → 변절 확인 → (미션 줄 없음) → 팀 주사위.
  - 위협은 2막 덱에서 뽑는다. 덱이 비면 2막 버린 더미를 섞는다.
  - 변절 확인(`_morning_traitor_check`)은 3단계에서 `act == 2`일 때 돌게 만들어 두었다.
- **팀 주사위:** 인원 + `rules.team_dice_extra` + `rules.scenes.act2_dice_extra`(새 키, 기본 0)개를 굴린다.
- **주사위 맡아 두기 (새, 2막 계획 단계):**
  - 액션: `{"type": "carry_die", "player", "die"}`
  - 아직 주인이 없는 팀 주사위를 "바칠 주사위"로 맡아 둔다. 몇 개든 맡을 수 있고, 이동 주사위(`take_die`)와는 따로다.
  - 맡은 주사위는 `team_dice[i]["owner"] = pid`, `["carry"] = true`로 표시한다.
  - `release_die`는 이동 주사위만 내려놓는다. 맡은 주사위를 내려놓는 액션은 `{"type": "drop_carry", "player", "die"}`이다.
  - `start_day` 조건은 1막과 같다: 감옥 밖 요원이 모두 이동 주사위를 가져야 한다.
  - 맡은 주사위는 그날 바치기에만 쓴다. 예비 주사위로 치지 않는다. 밤이 되면 사라진다.
  - 변절자는 `carry_die`를 할 수 없다.
- **결행 거점 진입:** 2막에는 결행 거점에 들어가도 경찰이 붙지 않는다 (카드 목록 4절 공통 규칙). 다른 거점은 1막과 같다.
- **변절자:** 3단계 5-3의 규칙을 그대로 쓴다 (늘 마지막 차례, 깔린 칸만 이동, 기습, 밀고).
- **밤:** 1막과 같은 처리를 한 뒤 장면의 "하루를 넘김" 조건을 센다 (3-5). 맡은 주사위와 오늘 기록(`check_pair` 성공 등)은 지운다.
- **판 끝:** `rounds_left`가 0이 되는 밤에 엔딩을 정한다 (5절).

## 3. 장면 (`scenes.json`)

### 3-1. 장면 카드
- 필드: `id`, `name`, `where`(`"inside"`|`"adjacent"`|`"inside_or_adjacent"`), `condition`, `on_fail`, `stop_text`.
- **장소:**
  - inside = 결행 거점 칸
  - adjacent = 결행 거점 칸의 상하좌우 칸 (보드 안)
  - inside_or_adjacent = 둘 다
  - 조건 안에 `where`가 따로 있으면 그것을 쓴다. 조건의 `where`가 거점 id(예: `"prison"`)면 결행 거점 안과 같다.
- **장면 자리에 있는 요원:** 갇히지 않은 요원(변절자 제외)이 장면 장소에 있으면 자리에 있는 것으로 본다.
  - 예외: **결행 거점 감옥에 갇힌 요원은 판정(`check`, `check_pair`) 조건에만** 참여할 수 있다 (19.13).
- 지금 장면은 `scenes[scene_index]` 하나뿐이다. 하루에 몇 장을 돌파해도 된다.
- 장면 진행 상태는 `scene_state`에 둔다. 새 장면이 열리면 비운다.
  - `{"paid_dice": 합, "paid_items": n, "paid_bombs": n, "hold_days": n, "pair_ok": [pid...], "people": [pid...]}`

### 3-2. 조건 kind와 돌파

| kind | 인자 | 시도하는 법 | 돌파 |
|---|---|---|---|
| `check` | `check`(판정 이름), `target` | 액션 `scene_check` (3-3) | 판정 성공 |
| `check_pair` | `check`, `count`, `same_day` | 액션 `scene_check` | 오늘 성공한 **서로 다른** 요원이 count명 |
| `dice` | `sum` | 액션 `scene_pay {"what": "die", "die": i}` | 바친 눈의 합(누적) ≥ sum − 첩보로 줄인 값 |
| `pay_item` | `count` | 액션 `scene_pay {"what": "item", "index": i}` | 바친 아이템 ≥ count |
| `pay_bomb` | `count`, `split` | 액션 `scene_pay {"what": "bomb"}` | 바친 폭탄 ≥ count. `split`이 false면 한 요원이 한 차례에 count개를 한꺼번에 바쳐야 함 (모자라면 액션 불가) |
| `people` | `count`, `where`, `same_day` | 자동: 장소에서 차례를 마친 요원을 기록 | 오늘 기록된 서로 다른 요원 ≥ count |
| `hold` | `where`, `days`, `count` | 자동: 밤에 장소의 요원 수를 셈 | 요원 ≥ count인 밤이 `days`번 (연속일 필요 없음) |
| `jailed_here` | – | 자동 | 결행 거점 감옥에 요원이 갇혀 있음. 장면이 열릴 때, 누가 갇힐 때 확인 |
| `any_of` | `options[]` | 각 선택지의 방법 | 어느 하나가 돌파 |
| `all_of` | `options[]` | 각 선택지의 방법 | 모두 돌파 (데이터에 아직 없지만 검증기 어휘에 있으므로 구현) |

- **기록의 범위:** "오늘" 기록(`check_pair`, `people`)은 밤에 지운다. 바치기와 `hold`는 장면이 바뀔 때까지 남는다.
- **`any_of` 진행 상태:** 선택지마다 따로 센다. 상태 키에 선택지 번호를 붙인다.
- **판정 이름**
  - 판정 이름은 기존 `_start_check`가 쓰는 캐릭터 보정 이름과 같다.
    - `"assassin"`: 저격수 오의 다시 굴림 등
    - `"evade"`: 윤 소위 자동 성공 등
  - `"generic"`·`"lock"`은 캐릭터 보정이 없는 판정이다.
  - 목표는 장면의 `target`이 정한다. 없으면 `rules.checks[이름]`을 쓴다.
  - `check_pair`의 목표는 `rules.checks[check]`를 쓴다.
- **보정**
  - 오늘 장면 판정 보정 `today.scene_mod`를 목표에 더한다 (「비상 소집」).
  - 첩보 토큰 (3-4)
  - **`scope: "strike"` 권리:** 사연 보상에서 받는다. `_grant_index(p, kind, true)`로 장면 판정에서만 쓴다 (3단계 2-4).

### 3-3. 장면 액션 (차례 중, 차례인 요원만)

**`{"type": "scene_check", "player"}`**
- 지금 장면에 `check`나 `check_pair` 선택지가 있어야 한다.
- 요원이 장면 장소에 있어야 한다. 결행 거점 감옥에 갇힌 요원도 된다.
- 한 차례에 장면 시도는 **한 번**이다 (`flags.scene_tried`).
- 갇힌 요원은 탈옥 대신 이 액션을 할 수 있다. 하고 나면 그 차례에 탈옥을 시도할 수 없다.
- 판정은 기존 판정 흐름(`_start_check`)을 그대로 쓴다. 다시 굴리기 선택, 예비 주사위 다시 굴리기, 권리도 그대로 쓴다.
- 판정 문맥 `ctx = "scene"`을 둔다.
- 결과 처리 (`_check_done` 분기):
  - 성공하면 돌파하거나 `pair_ok`에 더한다.
  - 실패하면 장면의 `on_fail`을 그 요원(self)으로 실행한다.
- `any_of`에 판정 선택지가 둘 이상이면 첫 번째 판정 선택지를 쓴다.

**`{"type": "scene_pay", "player", "what": "die"|"item"|"bomb", ...}`**
- 요원이 장면 장소에 있어야 하고, 갇혀 있지 않아야 한다.
- 바칠 수 있는 것:
  - `die`: 내가 맡은 주사위(`carry`), 또는 아직 쓰지 않은 예비 주사위. 이동 주사위는 안 된다.
  - `item`: 손의 아이템 1장 (버린 더미로)
  - `bomb`: 폭탄 1개. `split: false`이면 count개를 한꺼번에 바친다.
- 한 차례에 여러 번 바칠 수 있다. 장면 시도 1번 제한은 판정에만 적용한다.
- 바친 뒤 돌파 조건을 확인한다.

**`{"type": "use_intel", "player", "mode": "check"|"dice"}`**
- 첩보 토큰은 팀이 함께 쓴다. 한 개씩 쓴다.
- `check`: 이번 차례 내 다음 장면 판정 +`rules.intel_token.check_bonus`. 쌓을 수 있다 (`flags.intel_check`). 지금 장면에 판정 선택지가 있을 때만 쓴다.
- `dice`: 지금 장면의 `dice` 조건 필요 합을 `rules.intel_token.dice_reduce`만큼 줄인다 (`scene_state.dice_reduce`). 지금 장면에 `dice` 선택지가 있을 때만 쓴다.
- 장소와 상관없이 차례인 요원이 쓸 수 있다. 변절자는 쓸 수 없다.

**변절자는 장면 액션을 할 수 없다.**

### 3-4. 자동으로 세는 것
- `people`:
  - 요원이 차례를 마칠 때(`_finish_turn`) 그 요원이 장소에 있으면 기록한다.
  - `count`에 닿으면 그 요원이 돌파한 것으로 본다.
  - 2a의 협동 미션 `_where_match`를 참고한다.
- `hold`:
  - 밤(`_night`, 협동 미션 처리 뒤)에 장소에 있는 요원 수를 센다.
  - 돌파하면 by는 -1이다 (특정 요원 없음).
- `jailed_here`:
  - 장면이 열릴 때와 `_jail` 뒤에 확인한다.

### 3-5. 돌파 (`_scene_break(by_pid)`)
1. 알림 `{"kind": "scene_break", "index", "id", "player": by_pid}`, 배너, 연표, 로그를 남긴다.
2. 사연 훅을 부른다: `saga_strike_event(kind, by_pid, {"strike": target, "present": [결행 거점 칸에 있는 요원 id(갇히지 않음, 변절자 제외)]})`.
   - kind는 장면 위치에 따라 정한다: 첫 장 `"entry"`, 마지막 장 `"final"`, 그 사이 `"middle"`.
   - 「경비 강화」 장면도 middle이다.
3. **마지막 장면이면 결행 성공**이다. `_end_game(true)`로 판을 끝낸다 (5절).
4. 아니면 `scene_index += 1`, `scene_state = {}`. 다음 장면을 공개하고 `jailed_here`를 확인한다.

### 3-6. 남은 op (4단계 훅 채우기)
지금 `OPS_STAGE4`에 있는 op들을 구현하고, 스텁(`_op_stub_stage4`, "(4단계 미구현)")을 지운다.

| op | 인자 | 처리 |
|---|---|---|
| `search` | `range` | 결행 거점 칸에서 맨해튼 거리 ≤ range인 요원(갇히지 않음, 변절자 제외)이 차례로 회피 판정을 한다 (요원 번호순). 실패하면 그 요원에게 `police_attach`. 기존 판정 흐름을 쓴다 (선택이 끼면 큐로 이어 감) |
| `scene_check_mod_today` | `value` | `today.scene_mod += value` |
| `threat_flip` | – | 지금 막(act)의 위협 덱에서 1장을 바로 뒤집어 효과를 실행한다. 리더가 실행한다. 아침 위협과 같은 함수를 쓴다 |
| `check_or_jail` | `check` | 그 요원(self)이 판정한다. 실패하면 투옥된다 |
| `refill_supply` | – | `bomb_supply = rules.bomb_supply` (처음 값으로) |

`_check_done`에 문맥(ctx)별 분기가 있으니 `"scene"`, `"search"`, `"check_or_jail"`을 더한다.

## 4. 조회 (UI·AI용)
- `current_scene() -> Dictionary`: 장면 카드 + `{"index", "total", "state"}`. 1막이면 `{}`.
- `scene_place_cells() -> Array`: 지금 장면의 장소 칸들.
- `scene_options(p) -> Array`: 그 요원이 지금 할 수 있는 장면 액션 (legal_actions와 같은 규칙).
- `scene_need(i := -1) -> Dictionary`: 조건별 남은 양. 예: `{"dice": 3}`, `{"people": 1}`, `{"hold": 1}`.
- `intel_tokens`: 공개.

## 5. 엔딩

### 5-1. 언제
- **결행 성공:** 마지막 장면을 돌파한 순간. 즉시 끝낸다.
- **시간 끝:** `rounds_left`가 0이 되는 밤.
  - 2막이면 아래 실패 엔딩 셋 중 하나가 된다.
  - 1막이면 `"history"`가 된다. 강제 결행이 있어 정상적으로는 일어나지 않지만 처리는 둔다.

### 5-2. 엔딩 종류
| id | 조건 | 제목 | 본문 |
|---|---|---|---|
| `victory` | 마지막 장면 돌파 | `endings.victory.name` | `strikes[target].ending` |
| `fail_final` | 마지막 장면에서 멈춤 | `endings.fail_final.name` | 멈춘 장면의 `stop_text` + `endings.fail_final.text` |
| `fail_middle` | 진입은 돌파했고 마지막 전에서 멈춤 | `endings.operation.name` | 멈춘 장면의 `stop_text` + `endings.operation.text` |
| `history` | 진입 장면도 돌파하지 못함 (또는 1막에서 시간 끝) | `endings.history.name` | 진입 장면의 `stop_text`(2막일 때) + `endings.history.text` |

### 5-3. ending 딕셔너리
```
ending = {
  "id": 위 id,
  "won": bool,                      # 요원 팀이 이겼는가 (victory만 true)
  "target": 결행 거점 id 또는 "",
  "scene": 멈춘 장면 id 또는 "",
  "scene_index": int,
  "title": String, "text": String,  # 데이터에서 조립한 결말
  "traitor": traitor_id,
  "traitor_won": bool,              # 변절자가 있고 요원이 짐
  "epilogues": [ {"player": pid, "saga": id, "key": 후일담 키, "text": 문장, "done": bool, "traitor": bool} ... ]
}
```
- **후일담**
  - `epilogue_key(pid, won)`(3단계)로 키를 정하고, `sagas.json`의 `epilogue[key]` 문장을 쓴다.
  - 문장 앞에 소속 이름과 캐릭터 이름을 붙인다. 예: `"의병 포수 김개똥 — 광복의 날, 그는 …"`.
    - 소속 이름은 `characters.json`의 `factions[소속].name`에서 읽는다.
  - 문장이 `null`이면 같은 결과의 다른 쪽 키로 대신한다: `win_done`이 없으면 `win_fail`, `lose_done`이 없으면 `lose_fail`.
- **변절자가 있고 요원이 지면:** 본문 끝에 `endings.traitor_won.text`를 붙인다.
- 알림 `{"kind": "over"}`, 연표, 로그를 남긴다. `phase = "over"`.
- 기존 `_game_over(reason)`은 이 함수로 합친다.

## 6. 변절자와 2막
3단계에서 만든 변절자 규칙을 실제 2막 흐름에서 쓴다. 추가로 정할 것은 다음과 같다.
- 장면 조건을 세는 요원(인원, 버티기, 자리)에서 변절자를 늘 뺀다.
- 변절자 기습으로 갇힌 요원도 결행 거점 감옥이면 판정 장면에 참여할 수 있다.
- 요원이 모두 갇힌 날도 하루는 그대로 흐른다. 갇힌 요원은 차례에 탈옥이나 `scene_check`를 한다.
