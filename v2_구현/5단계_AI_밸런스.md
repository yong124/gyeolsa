# v2 구현 5단계: AI와 밸런스 수정

**구현자를 위한 안내:** 이 문서만 보고 작업할 수 있게 썼다. 대화 맥락은 필요 없다. 저장소는 `G:\Git\결사`, 브랜치는 `v2`이고, 게임 프로젝트는 `game/`(Godot 4.7.1, GDScript)이다.

## 왜 하는가

v2 엔진은 1~4단계로 완성됐다. 1막, 사연, 변절, 2막 장면 덱, 엔딩이 들어 있다. 그런데 지금 시험은 **무작위 봇**만 쓴다. 그래서 밸런스를 잴 수 없다. 4단계 엔진 시험 결과가 그 예다.

| 지표 | 무작위 봇 결과 | 문제 |
|---|---|---|
| 결행 방식 | 99%가 강제 결행 ("남은 날 2일") | 봇이 투표로 결행하지 않음 |
| 2막 길이 | 평균 2.05일 | 장면 4~6장을 2일에 뚫을 수 없음 |
| 결행 성공 | 0% | 96%가 진입 장면도 못 넘음 |

이 숫자에서 두 가지를 알 수 있다.
1. **목적을 갖고 두는 AI가 있어야** 밸런스를 잴 수 있다.
2. AI가 생겨도 **2막 길이가 구조적으로 모자랄 수 있다.** 강제 결행이 남은 날 2일에 일어나기 때문이다.

이번 단계에서 하는 일은 다음과 같다.
- (A) v2 AI를 만든다.
- (B) 밸런스 측정 도구를 만든다.
- (C) 데이터 수치를 조정해 목표 범위에 맞춘다.
- (D) 결과를 보고서로 남긴다.

## 0. 원칙

- **v1 코드는 고치지 않는다:** `scripts/core/rules.gd`, `ai.gd`, `game_data.gd`, v1 테스트.
- **데이터 주도.**
  - 엔진과 AI 코드에 카드, 장면, 사연, 캐릭터 id를 쓰지 않는다. AI도 데이터의 `op`, `condition.kind`, `stat`, `persona`를 보고 판단한다.
  - 테스트와 측정 도구는 출력 표를 만들 때 id를 써도 된다.
- **밸런스 조정은 데이터 수치만** 바꾼다 (`game/data/v2/*.json`).
  - 수치를 바꾸면 그 카드의 문장 필드(`text`, `condition_text`, `reward_text` 등)와 `카드_목록_v2.md`의 해당 줄도 함께 고친다.
  - **규칙 모양을 바꾸는 수정**(새 조건, 새 op, 흐름 변경)은 하지 않고 보고서에 **제안**으로만 적는다. 예외는 4-2의 `act2_min_days` 레버 하나다.
- **결정성:**
  - AI는 게임 상태만 보고 결정한다.
  - AI에 난수가 필요하면 엔진 `rng`를 건드리지 말고, 시드를 받은 별도 `RandomNumberGenerator`를 쓴다.
  - 같은 시드라면 AI 판도 재생이 맞아야 한다. AI가 고른 액션은 `actions`에 쌓이므로 재생은 엔진만으로 된다.
- 문장(로그, 보고서)은 한국어로 쓴다.

## 1. v2 AI (`game/scripts/core/v2/ai_v2.gd`, class_name `GameAIV2`)

### 1-1. 모양
```gdscript
static func decide(g: RulesV2, pid: int, persona := "") -> Dictionary
```
- pid 요원이 지금 보낼 액션 하나를 돌려준다. 보낼 것이 없으면 `{}`.
- 반드시 `g.legal_actions()` 안의 액션이어야 한다.
  - 마지막에 확인하고, 없으면 legal 중 무난한 것(`end_move`, `end_turn` 등)으로 대신한다.
  - 대신한 횟수는 세어서 측정 도구가 출력한다. **목표는 0**이다.
- 성격(persona)이 비어 있으면 `characters.json`의 `persona`를 쓴다 (`"bold"` 돌격 | `"careful"` 신중 | `"support"` 지원).

```gdscript
static func next_actor(g: RulesV2) -> int
```
- 지금 액션을 보낼 요원을 돌려준다.
- 계획 단계(plan)에서는 아직 할 일이 남은 요원 순으로 보낸다. 낮(day)에는 다음 차례를 정한다 (1-3). 선택(choice)에서는 선택을 맡은 요원이다.

**AI가 보는 정보:** AI는 사람과 같은 정보만 쓴다.
- **쓰지 않는 것:** 남의 사연 카드, 남의 심문 카드 내용, 덱 순서.
- **쓰는 것:** 공개 정보와 자기 비밀(`saga_cards(pid)`, `shaken_count(pid)`). 남의 심문 카드는 장수(`interrogation_count`)만 쓴다.
- **예외:** 위협 미리 보기는 `threat_preview()`가 허락하는 만큼만 쓴다.

### 1-2. 목표 고르기 (요원)
매 차례 아래 후보에 점수를 매겨 가장 높은 곳으로 간다. 점수는 "가치 ÷ (거리 + 위험)" 꼴로 한다. 가중치는 성격별 표로 파일 위쪽 상수에 모은다. 아래 순서는 대략의 우선순위다.

1. **결행 장면 (2막):** 지금 장면을 돌파하는 데 필요한 자리로 간다 (`scene_place_cells`).
2. **갇힌 동료 구출:** 가까우면 간다 (v1 `RESCUE_RANGE` 참고).
3. **공개 미션 줄 (1막):** 이룰 수 있는 미션의 타일이나 거점으로 간다. 협동 미션은 동료가 가는 중이면 가치를 올린다.
4. **내 사연:** `saga_progress`로 남은 양이 적을수록 가치를 올린다. 단 팀 목표보다 높게 두지 않는다 (기획서 19.7: "팀 일을 제칠 만큼은 아니게").
5. **설득:** 같은 칸 동료가 심문 카드 2장 이상이고 내게 예비 주사위가 있으면 한다. 「다방 밀담」, 「연락망」 능력도 같은 기준으로 쓴다.
6. **안전:**
   - 쫓기면 은신처, 따돌림 거리, 미끼를 고려한다.
   - 노출이 높고 경찰이 가까우면 거점 진입을 미룬다.
   - 성격별로 다르게 한다: careful은 위험 가중치를 크게, bold는 작게 둔다.

이동은 `path_to`와 `legal_steps`로 한 칸씩 보낸다. 검문소는 `evade_chance`를 보고 돌아갈지 정한다.

### 1-3. 하루 운영
- **아침 계획 (팀 주사위)**
  - 요원마다 오늘 목표까지 필요한 칸 수를 추정한다.
  - **필요가 가장 큰 사람부터 큰 눈을 배정**한다 (욕심쟁이 배정이면 충분하다).
  - 김개똥처럼 1·2를 3으로 바꾸는 특성(`move_min3` stat)이 있으면 작은 눈을 그 요원에게 준다.
  - 사연 조건이 주사위 눈인 요원(`take_die`, `take_lowest_die`)은 맞는 눈을 조금 더 선호한다. 팀 배정을 크게 해치지 않는 범위에서만 한다.
  - **2막:** 지금 장면이 `dice` 조건이면 남은 합에 맞춰 장면 자리로 가는 요원이 `carry_die`로 맡는다.
  - 아침 아이템과 능력(예: 「무전 지원」 주사위 다시 굴리기)은 배정 전에 쓸지 정한다. 작은 눈이 많을 때 쓴다.
- **차례 순서 (자유 순서):** 다음 순서로 먼저 움직인다.
  1. 다른 요원의 길을 열어 주는 요원 (구출, 협동 미션 앞사람)
  2. 경찰이 가까운 요원
  3. 나머지
  - 「이 차장」처럼 동료 옆으로 붙는 특성(`end_move_hop_to_ally`)이 있으면 늦게 움직인다.
  - 변절자는 엔진이 마지막으로 강제한다.
- **결행 투표**
  - `ready >= launch_min`이고 아래 셋을 모두 만족하면 찬성한다.
    - 목표 거점의 첩보 ≥ 2
    - 남은 날이 "추정 2막 필요 일수" 이상
    - 남은 날이 "더 기다렸을 때의 이득"보다 적다
  - 추정 2막 필요 일수 = 장면 수(진입 1 + 중간 + 「경비 강화」 + 마지막) × `ACT2_DAYS_PER_SCENE`(상수, 기본 0.8). 이 상수는 측정으로 다듬는다.
  - 성격별로 다르게 한다: bold는 일찍, careful은 늦게 찬성한다.
- **사연 남기기 (`saga_keep`):** 남은 양이 적은 쪽을 남긴다. 결행 갈래는 그 거점이 결행 목표이면 가치를 올린다.
- **선택 응답 (`choose`):** 선택 종류마다 무난한 기본 규칙을 둔다.
  - 다시 굴리기: 판정이 중요하면 쓴다.
  - 버릴 아이템: 가치가 낮은 것을 버린다.
  - 대상 고르기: 위협은 가장 안전한 요원에게, 도움은 가장 필요한 요원에게 보낸다.
  - 타일 고르기: 공개 미션에 필요한 타일을 고른다.
  - 「다방 밀담」: "흔들렸다"면 버린다.
  - 위협 묻기: 가장 나쁜 카드를 묻는다.
  - **모든 선택 종류에 응답이 있어야 한다.** 엔진의 선택 종류 목록과 대조하는 시험을 넣는다.
- **아이템 사용:** 아이템마다 쓰는 상황을 op로 판단한다.
  - `police_remove`: 쫓길 때
  - `checkpoint_pass`: 검문소 앞
  - `threat_bury`: 다음 위협이 나쁠 때
  - 반응 아이템은 엔진의 반응 선택에서 쓴다.
- **2막 장면**
  - 장면 자리에 서면 `scene_options`에서 고른다.
  - 판정은 성공률이 낮으면 첩보 토큰(`use_intel`)을 먼저 쓴다.
  - 바치기는 필요한 만큼만 한다.
  - `people`이나 `hold` 조건이면 동료와 같은 자리로 모인다.

### 1-4. 변절자 AI
v1 `ai.gd`의 `_traitor`를 옮긴다.
- **밀고:** 결행 거점에 가장 가까운 요원에게 한다.
- **기습:** 2막 장면 자리에 있는 요원을 우선한다. 「인원」·「버티기」 장면을 방해한다.
- **이동:** 깔린 칸으로만 다닌다 (`legal_steps`가 이미 제한함).

## 2. 측정 도구 (`game/tools/v2_balance.gd`)

헤드리스로 돌리는 스크립트다.
```
E:\Godot\Godot_v4.7.1-stable_win64_console.exe --headless --path game --script res://tools/v2_balance.gd -- [옵션]
```

**옵션**
| 옵션 | 뜻 |
|---|---|
| `games=N` | 판 수 (기본 400) |
| `seed=S` | 시작 시드. 판마다 S+i |
| `players=4` | 인원 (기본 4) |
| `set=경로=값` | rules.json 값을 이 실행에서만 바꿈. 여러 번 줄 수 있음. 예: `set=forced_launch_days_left=3` |
| `sweep=경로=값1,값2,…` | 값마다 같은 판 수를 돌려 표 하나로 비교 |
| `force_strike=거점 id` | 결행 목표를 그 거점으로 강제 (거점별 성공률 측정용) |
| `force_char=캐릭터 id` | 그 캐릭터를 반드시 넣음 (캐릭터별 영향 측정용) |
| `out=경로` | 결과 JSON 저장 (기본 `user://v2_balance.json`) |

- **데이터 덮어쓰기:** `GameDataV2.load_default()`로 읽은 뒤 사본을 만들어 `rules` 딕셔너리를 고친다. 파일은 바꾸지 않는다.
- **캐릭터:** 판마다 12명 중 무작위 4명을 넣는다. 시드에 따라 정해지고, 「2장 받아 1장 고르기」는 AI 없이 무작위로 한다.
- **판 진행:** `next_actor` → `decide` → `apply`를 반복한다. 액션 수 상한을 넘으면 "멈춘 판"으로 센다. **목표는 0판**이다.

**출력 지표 (표와 JSON)**
- **승패와 엔딩:** 승률(대성공), 엔딩 4종 비율, 표준오차
- **결행 시점:**
  - 결행 날의 평균과 분포 (작전 기간 대비 %)
  - 투표 결행 대 강제 결행 비율
  - 2막 길이의 평균과 분포
- **거점과 장면:**
  - 결행 거점 선택률
  - 거점별 성공률
  - 장면별 도달 수와 돌파율
  - 멈춘 장면 분포
- **변절:**
  - 변절이 일어난 판 비율 (결행 순간 / 2막 아침)
  - 변절 판과 그렇지 않은 판의 승률
- **사연:** 사연별 이룬 비율, 판당 이룬 수
- **캐릭터:** 그 캐릭터가 있는 판의 승률. 전체 승률과의 차이를 %p로 보인다.
- **기타:**
  - 판당 투옥, 탈옥, 구출, 설득, 심문 카드, 노출 최고값, 경계 단계 분포
  - 미션 종류별 성공 수
  - 위협 카드별 등장 수
  - AI 대체 액션 수, 멈춘 판 수

## 3. 목표 (4인 기준)

| 지표 | 목표 | 근거 |
|---|---|---|
| 승률 (대성공) | **45~55%** | 16.11, v1과 같음 |
| 결행 날 | 작전 기간의 **55~75%** 지점 | 16.11 |
| 투표 결행 비율 | **70% 이상** (강제 결행은 늦장 부린 판의 벌칙이어야 함) | 새 목표 |
| 2막 길이 | 평균 **3~4일**. 장면이 4~6장이므로 v1의 1~3일보다 길게 잡음 | 새 목표 |
| 거점 선택률 | 네 거점 각각 **15% 이상** | 16.11 |
| 거점별 성공률 (`force_strike`) | 서로 **15%p 이내** | 16.11 |
| 장면 돌파율 | 도달한 장면 중 돌파율이 **25% 미만인 장면 없음**, 마지막 장면은 40~70% | 새 목표 (막다른 장면 방지) |
| 변절 발생 | 4인 판의 **40~60%** | 19.8 ("절반쯤") |
| 변절 판 승률 | 변절 없는 판보다 **5~20%p 낮음** | 변절은 위협이되 판을 끝내지 않아야 함 |
| 사연 | 사연마다 이룬 비율 **20~70%**. 판당 이룬 수 1.5~2.5 (4명 중) | 19.7 |
| 캐릭터 | 캐릭터별 승률 차이 **±8%p 이내** | 19.14 |
| 멈춘 판, AI 대체 액션 | **0** | |

캐릭터 측정은 캐릭터마다 400판 이상 돌린다 (`force_char`). 표준오차가 ±2.5%p 안팎이 되게 한다.

## 4. 조정 레버와 순서

### 4-1. 순서
아래 순서대로 한 단계씩 맞춘다. 앞 단계가 뒤 단계에 영향을 주기 때문이다.

1. **기준선 측정:** 아무것도 바꾸지 않고 400판을 돌려 결과를 보고서에 남긴다.
2. **AI 다듬기**
   - 멈춘 판, 대체 액션, 이상한 행동을 고친다. 예: 장면 자리에 아무도 안 감, 사연만 쫓음.
   - 이건 **수치 조정이 아니라 AI 고치기**다. 수치를 바꾸기 전에 끝낸다.
3. **결행 시점과 2막 길이** (4-2)
4. **전체 승률:** 장면 수치, 작전 일수, 경찰
5. **거점별 균형:** 장면 수치를 거점별로 조정한다.
6. **변절:** 심문 덱 비율, 기준, 「회유 공작」 장수
7. **사연:** 조건의 횟수, 보상
8. **캐릭터:** 특성과 능력 수치

**한 번에 레버 하나**만 바꾸고 `sweep`으로 값 2~4개를 비교한다. 단계를 마칠 때마다 3단계(결행 시점)부터 다시 확인해 앞 단계가 깨지지 않았는지 본다.

### 4-2. 결행 시점과 2막 길이 (가장 먼저 풀 것)
아래 순서로 시도하고, 앞에서 목표에 닿으면 멈춘다.

1. **AI 투표 개선만으로** 투표 결행 70%, 2막 3~4일이 되는지 본다 (1-3의 투표 규칙).
2. `forced_launch_days_left`: 2 → 3, 4, 5를 비교한다. 강제 결행이 늦어서 2막이 짧아지는 것을 막는다.
3. `launch_min`: 5 → 4, 3을 비교한다. 결행을 더 일찍 열 수 있게 한다.
4. `rounds`: 10 → 11, 12를 비교한다. 1막 기간은 그대로 두고 2막 시간을 늘리는 효과다.
5. **새 레버 `act2_min_days`** (위에서 안 될 때만 켠다)
   - 결행할 때 `rounds_left < act2_min_days`이면 `rounds_left = act2_min_days`로 늘린다.
   - "결행하면 2막은 최소 N일"이라는 뜻이다. 기본값 0은 꺼짐이다.
   - 엔진(`_begin_act2`)에 이 값을 읽는 몇 줄을 더한다. 이번 단계에서 허용하는 유일한 규칙 변경이다.
   - 이 레버를 켜면 보고서에 "규칙 변경 제안"으로 따로 적는다. 사람이 결정한다.

### 4-3. 레버 목록

| 범주 | 파일과 키 | 범위 (벗어나면 보고서에 이유를 적음) |
|---|---|---|
| 작전 기간 | `rules.rounds`, `forced_launch_days_left`, `launch_min` | rounds 9~13 |
| 2막 | `rules.scenes.middle_draw` (2 고정 권장), `reinforce_by_alert`, `act2_dice_extra`, `act2_min_days`, `intel_token.*` | |
| 장면 | `scenes.json`의 `target`, `sum`, `count`, `days` | 판정 목표 7~11, 주사위 합 5~10 |
| 경찰과 노출 | `rules.police.*`, `exposure.*` | |
| 판정 | `rules.checks.*` | 6~10 |
| 팀 주사위 | `rules.team_dice_extra` | 0~2 |
| 위협 | `threats.json`의 `count`, 효과 수치 | 1막 덱 장수는 20~28 |
| 변절 | `interrogation.json` 카드 `count` (전체 12장 유지 권장), `rules.traitor.shaken_needed`, 「회유 공작」 `count`, `rules.persuade.cards` | |
| 사연 | `sagas.json` 조건의 `count`, `range`, 보상 효과 수치 | 보상은 "아이템 한 장" 수준을 넘지 않게 (19.7) |
| 캐릭터 | `characters.json` 특성 `mods.value`, 능력 효과 수치 | |
| 미션 | `missions.json` 보상, `rules.mission_row` | |

**하지 않는 것**
- 카드를 새로 만들거나 빼지 않는다. 장수 조정은 된다.
- 조건 종류를 바꾸지 않는다.
- 캐릭터의 능력을 다른 능력으로 바꾸지 않는다.

이런 수정이 필요해 보이면 보고서의 "규칙 변경 제안"에 적는다.
