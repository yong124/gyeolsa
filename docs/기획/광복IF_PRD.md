## 1. 문제 정의

**지금 빌드는 규칙이 돌아가는 "시뮬레이터"이지, 플레이어가 몰입하는 "게임"이 아닙니다.** 규칙 엔진·AI·밸런스는 검증을 마쳤습니다(인원별 대성공 49~57%, 불법 액션 0건). 하지만 처음 켠 사람이 30분 동안 앉아 있을 이유를 주지 못합니다. itch.io에서 무료 게임은 첫 5분 안에 이탈 여부가 갈리므로, 이 상태로 배포하면 대부분 튜토리얼도 없이 로그만 보다 창을 닫게 됩니다.

### 1.1 현재 빌드 진단 (코드 기준)

| # | 증상 | 원인 (현재 구현) | 플레이어가 느끼는 것 |
|---|---|---|---|
| D1 | 말이 순간이동한다 | `BoardView`가 상태를 매 프레임 다시 그릴 뿐 이동 애니메이션이 없음 | 무슨 일이 일어났는지 못 봄 |
| D2 | 주사위가 텍스트다 | 판정 결과가 `"암살 주사위: 4 + 5 = 9"` 문자열 한 줄 | 판정의 긴장감이 없음 |
| D3 | 정보가 로그에 묻힌다 | 체포·미션 성공·일제 동향이 모두 오른쪽 로그 한 줄 | 중요한 순간을 놓침 |
| D4 | AI 차례가 너무 길고 불투명하다 | AI 3명이 0.35초 간격으로 수십 개 행동 | 구경만 하는 시간이 김, 동료가 뭘 하려는지 모름 |
| D5 | 규칙을 알려 주지 않는다 | 타이틀의 도움말 3줄뿐 | 무엇을 해야 할지 모름 |
| D6 | 내 선택이 가볍다 | 주사위 굴리기 → 초록 칸 클릭의 반복. 위험·경로 정보가 없음 | "내가 한 게 없다"는 느낌 |
| D7 | 소리가 없다 | 오디오 없음 | 피드백·분위기 부재 |
| D8 | 인물이 없다 | 요원 이름이 "동지 1 (조선의용대)" | 감정 이입 대상 없음 |
| D9 | 판이 끝나면 끝이다 | 엔딩 텍스트 + "타이틀로" 버튼 | 다시 할 이유 없음 |
| D10 | 게임다운 기본기가 없다 | 설정·일시정지·저장·전체화면 없음 | 완성되지 않은 인상 |

### 1.2 기회
- **소재의 힘:** "8월 15일 이전에 우리 힘으로 광복을 이룬다면?"이라는 역사 IF 설정은 분명한 감정 동기가 됩니다. 이 테마를 연출로 살리면 규칙이 같아도 체감이 크게 달라집니다.
- **검증된 코어:** 규칙과 밸런스가 이미 데이터로 분리되어 있어서, 남은 1개월을 온전히 "경험"에 쓸 수 있습니다.

## 5. 사용자 스토리 (우선순위순)

### 첫 경험 (P1)
1. 처음 켠 플레이어로서, **5분 안에 게임 방법을 직접 해 보며 배우고 싶다.** 그래야 규칙서를 읽지 않고 바로 즐길 수 있다.
2. 처음 켠 플레이어로서, **지금 무엇을 해야 하는지 화면에서 바로 알고 싶다.** 그래야 막히지 않는다. (다음 행동 안내, 미션 목표 위치 표시)
3. 처음 켠 플레이어로서, **내 선택이 얼마나 위험한지 보고 결정하고 싶다.** 그래야 운이 아니라 판단으로 이겼다고 느낀다. (성공 확률, 경찰 위험 범위)

### 한 판의 몰입 (P1, P2)
4. 플레이어로서, **주사위 판정 순간을 두근거리며 지켜보고 싶다.** 그래야 암살 성공이 짜릿하다.
5. 플레이어로서, **동료 AI가 무엇을 하려는지 알고 싶다.** 그래야 협력하고 있다고 느낀다.
6. 플레이어로서, **AI 차례를 원하는 속도로 보고 싶다.** 그래야 기다리다 지치지 않는다.
7. 플레이어로서, **날짜가 넘어갈 때마다 8월 15일이 다가오는 압박을 느끼고 싶다.** 그래야 시간 제한이 이야기가 된다.
8. 플레이어로서, **동료가 잡혀 갔을 때 구하러 갈지 고민하고 싶다.** 그래야 협력 게임답다.

### 끝난 뒤 (P1, P2)
9. 플레이어로서, **결말에서 우리가 한 일을 돌아보고 싶다.** 그래야 결말이 내 이야기처럼 느껴진다.
10. 플레이어로서, **실제 역사에서는 어땠는지 알고 싶다.** 그래야 IF 설정의 의미를 이해한다.
11. 플레이어로서, **더 어렵게, 또는 다른 세력으로 다시 해 보고 싶다.** 그래야 두 번째 판을 시작한다.

### 기본기 (전체)
12. 플레이어로서, **중간에 끄고 나중에 이어 하고 싶다.**
13. 플레이어로서, **소리 크기, 화면 모드, AI 속도를 조절하고 싶다.**

### 예외 상황
14. 감옥에 갇힌 플레이어로서, **할 수 있는 일(탈옥, 옷핀)과 동료의 구출 가능성을 알고 싶다.** 그래야 멍하니 기다리지 않는다.
15. 선택지가 떴을 때(버리기, 연막탄 등) **각 선택의 결과를 미리 보고 싶다.**

| 항목 | 요구사항 | 수락 기준 |
|---|---|---|
| R1.1 말 이동 | 요원·경찰이 칸 단위로 부드럽게 이동 (칸당 0.12초 트윈, 속도 설정에 비례) | 순간이동이 없음. 경찰 체포 시 경찰이 요원 칸까지 이동한 뒤 체포 연출 |
| R1.2 타일 공개 | 새 타일이 뒷면에서 뒤집히며 등장 (0.3초) | 검문소가 나오면 붉은 경고 효과 + 효과음 |
| R1.3 주사위 | 화면 중앙에서 주사위가 굴러 결과에서 멈춤 (0.8초). 판정은 목표값과 보정치를 함께 표시 | 판정 전 "목표 9 이상 · 성공 확률 28%" 표시. 성공은 금색, 실패는 붉은색 강조 |
| R1.4 결과 스팅어 | 미션 성공·체포·투옥·구출·탈옥에 중앙 배너 (1.2초) | 해당 상황에서 로그를 보지 않아도 알 수 있음 |
| R1.5 광복수치 | 수치가 오를 때 트랙이 차오르고 숫자가 튀어 오름 | 목표치 도달 시 전용 연출 후 엔딩으로 전환 |
| R1.6 날짜 전환 | 날짜가 넘어갈 때 달력이 넘어가는 전환 (1초) + 경계 단계 변화 안내 | 경계 단계가 오를 때 "경찰 이동 3칸"처럼 변화를 명시 |

> **기술 메모:** 규칙 엔진은 즉시 상태를 바꾸므로, UI가 `events` 큐를 **순서대로 재생하는 연출 큐**(애니메이션 → 다음 이벤트)로 바뀌어야 합니다. 엔진은 연출에 필요한 이벤트(`move` 경로, `police_move`, `catch` 등)를 더 자세히 내보냅니다.
