# 결사 — 게임기획 포트폴리오 목차 초안

제출용 · 2026-10-08

목표: 자료만 읽어도 게임의 핵심과 기획 판단, 검증 결과를 이해할 수 있도록 구성한다. 현재는 목차만 정하며 PPT 제작과 페이지별 본문 작성은 진행하지 않는다.

## 본편

### 1. 프로젝트 개요
- 게임 콘셉트 · 장르 · 플랫폼 · 플레이 방식
- 담당 업무와 제작 도구
- 현재 구현 범위

### 2. 핵심 플레이와 설계 목표
- 1막 준비 → 결행 결정 → 2막 돌파
- 주사위 사용 · 동료 협력 · 결행 시점의 선택
- 핵심 화면과 주요 정보

### 3. 행동 시스템 설계
- 초기 행동 구조의 문제
- 개인 주사위와 행동 제한의 대안 비교
- 주사위 하나 = 행동 하나
- 이동과 판정의 기회비용

### 4. 협력 구조와 긴장 설계
- 변절 규칙을 제거한 이유
- 개인 사연과 팀 승리 목표
- 경찰 추격 · 일제 동향 · 결행 혜택
- 규칙을 줄이면서 유지한 선택과 압박

### 5. 미션 콘텐츠 설계
- 미션을 지도에 연결하는 방식
- 미션별 행동과 필요 자원의 차이
- 대표 미션 3개 비교
- 거점 안 미션을 거점 옆 칸으로 변경한 이유

### 6. 밸런스 검증과 개선
- 측정 목표와 실험 조건
- 규칙 문제와 AI 판단 문제의 구분
- 거점별 난이도 조정
- 최신 결과와 자동 측정의 한계

### 7. 첫 플레이 안내 개선
- 기존 안내의 문제
- 개념 설명과 직접 행동을 연결한 튜토리얼
- 구현 확인 결과와 학습 효과의 검증 과제

### 8. 결과와 후속 과제
- 설계 목표별 구현 결과
- 남은 문제와 사람 플레이테스트 계획
- 플레이 링크와 상세 자료

## 선택 부록
- 상세 규칙 요약
- 카드·캐릭터 데이터 예시
- 밸런스 상세 표와 측정 조건
- 기획 지시서와 검수 기록 예시

## 편집 기준
- 발표 없이 읽히도록 각 사례에 문제 → 판단 근거 → 결정 → 결과를 포함한다.
- 게임 설명은 사례를 이해하는 데 필요한 범위로 제한한다.
- 화면에는 위치·조건·변경점을 표시해 본문과 연결한다.
- 자동 측정 결과와 사람의 재미·이해도 검증을 구분한다.
- 원작·디지털판 구분을 제목과 목차에 내세우지 않는다. 담당 업무를 구체적으로 표기하고, 전체를 단독 제작했다고 적지 않는다.
- 페이지 수와 디자인은 목차를 확정한 뒤 정한다.
