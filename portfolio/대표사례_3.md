## 사례 A. 큰 주사위를 이동에 쓸까, 판정에 남길까?

**문제:** 팀 주사위를 나누는 초기 구조에서는 사람이 먼저 고르고 AI가 남은 것을 가져갔다. 1인과 AI 동료가 함께하는 환경에서 분배의 협의가 약했고, 예비 주사위의 사용에도 다른 행동을 포기하는 비용이 부족했다.

**판단:** 고정 행동 점수는 행동량을 일정하게 만들지만 이동의 운 요소를 줄이고 관련 수치를 다시 맞춰야 했다. 개인 작전 주사위는 공개된 눈을 보고 이동과 판정의 배분을 선택하게 할 수 있었다. 레퍼런스를 비교한 뒤 개인 작전 주사위를 선택했다.

**결정:** 이동은 낸 눈만큼의 거리, 작전 판정은 낸 눈과 새 주사위의 합을 사용한다. 후속 행동 제한으로 같은 주사위를 다시 쓰지 못하게 했다.

**규칙 설명용 가상 상황:** 내 주사위는 6과 3, 판정 목표는 9다. 보정·아이템·특성은 제외한다.

| 오늘의 목적 | 배분 | 얻는 것과 포기하는 것 |
|---|---|---|
| 3칸 거리의 미션 수행 | 3으로 이동·6으로 판정 | 오늘 판정 가능, 성공 확률 66.7% |
| 6칸 거리의 다른 목적지로 이동 | 6으로 이동·3을 다른 행동에 사용 | 먼 목적지 도달, 6으로 판정할 기회 포기 |

눈 3을 목표 9 판정에 쓰면 성공 확률은 16.7%다. 큰 눈은 이동과 판정 모두에 가치가 있어 위치와 목적에 따라 사용처가 달라진다. 특정 선택이 항상 정답이라는 예시로 쓰지 않는다.

**결과:** 이동과 판정을 같은 자원으로 연결하고 예비 주사위 메뉴를 제거했다. 도입 직후 AI 4명 300판 승률은 46%, 이전 기록은 약 47~48%다. 난이도가 같거나 사람의 고민이 늘었다는 증거로 해석하지 않는다.

## 사례 B. 설계 의도를 구현 조건으로 전달하고 검수하다

**문제와 결정:** 개인 주사위 도입 이후에도 한 차례에 여러 일을 할 수 있어 포기할 행동을 고르는 구조가 약했다. 본인이 `주사위 하나 = 행동 하나`를 선택하고, 비용·예외·차례 종료를 설계했다.

**AI에 맡긴 작업:** 차례 구조 지시서로 엔진·화면·AI 동료·저장·시험의 변경 범위와 완료 기준을 전달했다. AI는 구현·시험·자동 측정·보고를 수행했다. 설계 정리와 보고서 검토에도 AI 보조를 활용했고, 본인은 결정·검수·우선순위를 담당했다.

실제 지시서 발췌:

> 낮을 **「주사위 1개 = 행동 1개」**로 바꾼다.
>
> 차례가 끝나는 조건을 「이동을 마치면」에서 **`end_turn`(차례 마치기)**으로 바꾼다.
>
> 행동마다 주사위 하나를 고르고, 쓴 주사위는 `used`가 된다.
>
> 측정만: 300판 전후를 기록한다. 행동이 줄어 승률이 크게 떨어져도 수치는 고치지 마라. 밸런스는 G단계에서 잡는다.

| 보고된 결과 | 판단 |
|---|---|
| 당시 규칙 시험 789개 통과·실패 0 | 지정한 조건의 구현 확인 자료로 사용 |
| AI 300판 승률 50.3%→61.7% | 같은 칸 허용·경찰 따돌림 거리 변경도 포함돼 단일 원인으로 해석하지 않음. 밸런스 단계로 분리 |
| 숨기 사용 판당 0.0회 | 새 행동을 AI가 활용하지 않는 문제를 후속 개선 과제로 기록 |
| 주사위 미사용 비율 44.5% | 미사용을 오류로 단정하지 않고 AI가 행동 기회를 놓치는지 확인할 지표로 사용 |

**결과:** 주사위 소비와 차례 종료가 연결된 행동 구조를 구현했다. 시험 통과와 실제 플레이 문제를 구분하고 밸런스·AI 개선을 별도 과제로 남겼다. 직접 발견한 투옥 문제는 사례 C에서만 상세히 다룬다.

## 사례 C. 미션 수행 중 반복되는 투옥을 발견하고 구조를 바꾸다

**관찰:** 직접 플레이에서 거점 진입 후 경찰에 잡혀 미션을 이어가기 어려운 상황을 발견했다. 규칙 시험 통과와 별개로 미션 요구 행동과 경찰 등장 규칙이 충돌했다.

**원인과 첫 수정:** 경찰은 요원에게 가장 가까운 거점에서 등장했다. 거점 안에 있는 요원에게는 현재 칸이 등장 위치가 될 수 있었다. 거점 안이나 곁에서 붙는 경찰은 3칸 떨어져 등장하도록 수정했다.

**두 번째 결정:** 첫 수정 이후에도 거점 진입을 요구하는 미션 구조는 남았다. 후속 검수에서 1막은 준비, 2막은 거점 돌파라는 구분에 맞춰 미션 5장의 수행 장소를 거점 옆 칸으로 옮겼다. 기존 수행 조건을 재사용하고 카드 ID·보상·결행 준비 값을 유지해 저장·사연·특성의 연결을 보존했다.

| 미션 | 변경 전 | 변경 후 |
|---|---|---|
| 형무소 간수 매수 | 형무소 진입 | 옆 칸에서 주사위 합 6을 바침 |
| 총독부 설계도 입수 | 총독부 진입 | 옆 칸에서 쫓기지 않고 차례 종료 |
| 경찰서 문서 탈취 | 내부에서 문서를 받아 반출 | 옆 칸에서 받아 출발점까지 운반 |
| 군영 보급 장부 | 내부에서 장부 수령 | 옆 칸에서 받아 시내로 운반 |
| 엄호 잠입→경찰서 앞 양동 | 한 요원 진입·다른 요원 인접 | 두 요원이 같은 날 경찰서 옆 칸에서 차례 종료 |

**결과:** 미션 변경 전후 AI 4명 1,000판 승률은 55.2%와 54.4%로 기록됐다. AI 시험 220판에서 멈춤·반칙 0으로 보고됐다. 변경 버전의 진행을 확인한 자료이며, 투옥 문제의 완전 해결이나 사람의 난이도 개선을 입증하지 않는다.

**판단의 의미:** 경찰 등장 거리 수정은 직접 충돌을 줄이고, 미션 장소 변경은 준비와 돌파의 역할을 나눈다. 개별 수치와 미션 요구 행동을 함께 검토했다.

**출처:** 등장 거리 수정 커밋 `652192b`, 미션 수정 커밋 `dca02a0`, [공개 이후 수정 기록](../v2_구현/지시서/P_출시후_다듬기.md) P1.

**증거 배치:** PDF 8쪽에 경찰 등장 위치 도식, 9쪽에 대표 미션 변경 전후와 최신 카드·옆 칸 마커 캡처. 최신 대표 카드 캡처는 추가 확보가 필요하다. 변경 전 도식은 문서 기반 재구성이라고 표시한다.

## 수치·표현 정리

- `3차례 안 투옥 39%→34%`의 원측정 자료는 현재 확인한 근거 문서에서 찾지 못해 제출 본문에서 제외했다. 거점 밖 `차례당 17.5%`와도 분모·기간이 달라 직접 비교하지 않는다.
- `승률 오차 ±3.5%p`는 산출식·신뢰수준이 확인되지 않아 제외했다.
- `평균 확률은 같다`, `난이도는 그대로`, `고민만 바꿨다`는 검증 범위를 넘어서므로 쓰지 않는다.
- 일제 작전 해결률 개선 분석은 AI 작업 세션이 수행했다. 본인이 직접 발견한 사례로 쓰지 않는다.
- 능력·아이템에는 주사위 소비와 사용 한도의 예외가 있다. `모든 능력은 무료`라고 쓰지 않는다.
- 원작·디지털판 구분과 전체 단독 구현 표현은 사용하지 않는다.
